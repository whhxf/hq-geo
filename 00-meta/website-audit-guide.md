# 官网 AI 友好度体检指南

> 基于夫唯"AI 信源型官网"三层模型。在生成任何 GEO 内容之前，先检查你的官网本身是否做好了被 AI 理解和引用的准备。

## 为什么官网体检是 GEO 的第一步

夫唯把"打造 AI 信源型官网"放在 GEO 5 件事的第 2 位（仅次于百科注册），逻辑是：

- **百科告诉 AI"你是谁"**（实体锚点）
- **官网告诉 AI"你为什么值得推荐"**（权威信源）

一个 AI 无法理解的官网，发再多外部内容也只是在补漏洞。官网做好了，外部内容才有根基。

## 使用时机

- **01-intent 运行前**：体检结果影响关键词优先级（官网缺失的维度 → 优先做内容）
- **03-content 运行前**：体检结果决定内容策略（基础层缺什么 → 先补基础内容）
- **06-source-pool 运行前**：官网弱项 → 信源池优先补强

## 三层体检清单

### 第一层：基础层（AI 能不能认识你）

| # | 检查项 | 合格标准 | 当前状态 |
|---|--------|---------|---------|
| 1.1 | 关于我们 | 有独立页面，清晰阐述品牌定位、使命、核心价值观（≥200字） | ⬜ 通过 / ⬜ 缺失 / ⬜ 不足 |
| 1.2 | 产品/服务分类 | 结构化展示（列表/卡片/表格），每项产品有名称+一句话描述+链接 | ⬜ 通过 / ⬜ 缺失 / ⬜ 不足 |
| 1.3 | 联系我们 | 有真实地址、电话、邮箱（至少两项），信息可交叉验证 | ⬜ 通过 / ⬜ 缺失 / ⬜ 不足 |
| 1.4 | ICP 备案 | 已完成备案且备案号在网站底部可见（AI 判断网站合法性的重要依据） | ⬜ 通过 / ⬜ 未备案 |
| 1.5 | 品牌名称一致性 | 全站品牌名统一（中文名+英文名），无混用、缩写不一致 | ⬜ 通过 / ⬜ 存在问题 |

**判定**：5 项全部通过 → 基础层合格，进入第二层。有缺失 → 优先补齐基础层再考虑内容生产。

### 第二层：场景层（AI 能不能理解你解决什么问题）

> 核心原则：AI 不理解"功能列表"，但能理解"谁 + 在什么情况下 + 用什么功能 + 解决了什么问题"。

| # | 检查项 | 合格标准 | 当前状态 |
|---|--------|---------|---------|
| 2.1 | 场景方案页 | 至少 3 个按人群/场景分类的解决方案页（如"上班族方案""多宠家庭方案"），每个方案页 ≥300字 | ⬜ 通过 / ⬜ 缺失 / ⬜ 不足 |
| 2.2 | 人群-问题-功能映射 | 每个场景页明确写了：目标人群身份 → 核心痛点 → 对应产品功能 → 预期结果 | ⬜ 通过 / ⬜ 缺失 / ⬜ 不足 |
| 2.3 | 场景页结构化 | 每个场景页有独立 URL、H1 标题含场景关键词、可被 AI 独立索引 | ⬜ 通过 / ⬜ 缺失 / ⬜ 不足 |

**判定**：3 项全部通过 → 场景层合格，进入第三层。缺失场景方案页是大多数 B2B 官网的通病——产品功能列了一堆，但 AI 不知道你的产品"适合谁、解决什么具体问题"。

### 第三层：知识层（AI 会不会引用你的内容）

| # | 检查项 | 合格标准 | 当前状态 |
|---|--------|---------|---------|
| 3.1 | 技术文章/教程 | ≥5 篇深度教程，每篇≥800字，含具体操作步骤和数据 | ⬜ 通过 / ⬜ 不足（<5篇） / ⬜ 缺失 |
| 3.2 | FAQ/痛点解析 | ≥10 条 FAQ，覆盖用户最常见的购买决策问题，每条直接回答 | ⬜ 通过 / ⬜ 不足（<10条） / ⬜ 缺失 |
| 3.3 | 产品对比/测评 | ≥2 篇客观产品对比（含竞品），含数据对比表 | ⬜ 通过 / ⬜ 不足 / ⬜ 缺失 |
| 3.4 | 结构化数据 | 全站有 Organization Schema，文章页有 Article/FAQ Schema（JSON-LD） | ⬜ 通过 / ⬜ 部分 / ⬜ 缺失 |
| 3.5 | llms.txt | 网站根目录有 `/llms.txt`，包含品牌简介+核心页面索引 | ⬜ 通过 / ⬜ 缺失 |

**判定**：薄弱项就是 03-content 的优先生产方向。

## 体检后的决策路由

```
体检完成
    ↓
基础层未通过 → 优先修官网（补齐关于我们/产品分类/备案）
    │           → 01-intent 推迟或仅生成 Definition 层关键词（先解决"AI不认识你"的问题）
    │
场景层未通过 → 01-intent 优先生成场景词（scenario 类型关键词）
    │           → 03-content 优先用 scenario 模板写场景方案页
    │
知识层未通过 → 01-intent 生成对应内容类型的关键词
    │           → 03-content 按模板生产（FAQ缺→faq模板，教程缺→howto模板，对比缺→comparison模板）
    │
三层全部通过 → 官网已是AI信源型，外部内容策略可以全面展开
```

## 与其他模块的协作

- **01-intent**：体检结果影响关键词优先级。官网缺场景 → 场景词优先级+2
- **03-content**：体检结果决定内容类型。知识层缺 FAQ → 优先生产 FAQ 内容
- **06-source-pool**：官网弱项 → 信源池优先补强对应平台（如备案缺失→优先企业数据库注册）
- **04-monitor**：官网体检通过后，监控才能反映真实效果

## 定期复检

建议每季度复检一次。AI 平台的引用偏好和算法在变，官网也需要同步进化。
