# 08 · 系统边界：hq-geo 与 hq-chuhai

**状态：** 已定（2026-10-10，Conan 提出）
**适用范围：** 本仓库全部模块 + 所有项目根
**真源级别：** 边界的唯一真源。两边引用本文，不各写一份。

## 一、为什么需要这份文件

hq-geo 与 hq-chuhai 曾经重叠。证据：

- `hq-chuhai/projects/quotestitch/` 同时是两套系统的实例根。它有自己的 `.hq-geo.json`。
- 选词方法两份。本仓库 `capabilities/keyword-research/`，chuhai `keyword-research/`。
- 分发渠道重叠。小红书、抖音、视频号在两处都记。
- 门禁两套。`test/run_quality_gate.py` 与 chuhai 的 `system/tests/run.sh`。

根因是切分轴错了。

两系统按「活动」分：一个做内容，一个做建站。
但内容和 SEO 是同一根价值链上的相邻环节。
按活动分，必然重叠。

---

## 二、唯一判据

**这份产出最终挂在自己拥有的域名上吗？**

- 是 → **hq-chuhai**
- 否 → **hq-geo**

这条轴互斥且穷尽。每个产出都能判，且只归一边。

判不出来时，问一句：这份产出的最终消费者，是自有域名上的访客，还是平台上的读者？

**判据读的是「产出服务的资产」，不是「产出暂时落在哪」。**

唯一的例外是**外链**。它的载体是别人的域名，但归 hq-chuhai。
理由：外链的价值在「指向谁」，只有 SEO 特别在意这一点。见第四节。

## 三、两个身份

| | hq-chuhai | hq-geo |
|---|---|---|
| 一句话 | 自有资产运营 | 外部渠道内容营销 |
| 资产 | 自己拥有的域名 | 别人的平台账号 |
| 目标 | 自有域名拿自然流量 | 平台留下可信署名内容 |
| 手段 | 建站 · 页面 SEO · 外链 · 变现 | 内容创作 · 平台适配 · 分发 |
| 闭环 | 排名 → 流量 → 收入 | 曝光 → 互动 → 线索 |

hq-chuhai 是**方向**。hq-geo 是**方法层 + 一个方向**。见第六节。

## 四、归属表

| 项 | 归属 | 理由 |
|---|---|---|
| 建站 · 部署 · 技术 SEO | hq-chuhai | 自有域名的属性 |
| 页面 SEO（标题 / H1 / 内链 / schema） | hq-chuhai | 页面的属性 |
| 外链 · 目录提交 | hq-chuhai | 指向自有域名。**判据的唯一例外** |
| 选词（Google / 英文 / Ahrefs） | hq-chuhai | 服务自有域名排名 |
| 自有站内容（博客页 / 工具页文案） | hq-chuhai | 挂在自有域名 |
| 内容创作方法 · 排版 · 图片契约 | hq-geo | 方法层，两边共用 |
| 第三方平台分发（小红书 / 知乎 / Reddit / X） | hq-geo | 载体是别人的平台 |
| 选词（小红书 / 抖音 / 微信） | hq-geo | 服务平台内容 |
| 渠道操作手册 | hq-geo | 载体知识，属方法层。**未实现**，见下 |
| 推广动作台账 | hq-chuhai | 记的是推广自有站的动作 |

**边界情形三条：**

- 自有站上的一篇文章。资产归 hq-chuhai，写作方法借 hq-geo。
- 一条推广自有站的平台帖。目的归 hq-chuhai，载体与写法归 hq-geo。
- 一条外链。载体在别人的域名，仍归 hq-chuhai。这是判据的唯一例外。

### 官网内容怎么分（最易判错）

官网内容横跨两边。要分开看，不能整块归一边。

| 部分 | 归谁 | 例子 |
|---|---|---|
| 内容方法 | **hq-geo** | 官网渲染器 · Schema 选择 · llms.txt · 发布前检查 · 排版契约 |
| 资产与实施 | **hq-chuhai** | 页面文件 · 部署 · 页面 SEO · 内链 · 外链 |

推论有三条：

1. `AGENTS.md` 的渠道清单里保留「自有博客」是对的。它指的是**方法**，不是资产。
2. 技能 `geo-website-renderer` 继续留在本仓库。它产出的是待落页的版本，不是页面本身。
3. 落页、部署、页面 SEO 不在本仓库。

**所以不用去改 `AGENTS.md` 和 `skills/` 里的「自有博客」。** 它们是方法层的声明，与判据不冲突。

## 五、SEO 与内容营销为什么不再重叠

**SEO 不是一个活动。它是自有资产的属性。**

- 一个页面的 SEO，是这个页面的属性。页面在哪，SEO 在哪。
- 自有域名上的页面 → hq-chuhai。
- 第三方平台上的内容没有 SEO。它只有平台推荐算法 → hq-geo。

推论：不用问「谁做 SEO」。只问「这个页面挂在谁的域名上」。

## 六、hq-geo 的两个身份

本仓库同时是两件事：

1. **方法层** — `capabilities/` `skills/` `test/` `00-meta/`。服务所有方向，两边共用。
2. **平台内容方向** — 项目根（如 kingsway 数字员工）。本仓库自己的业务。

hq-chuhai 是**自有资产方向**。它**引用**本仓库的方法，不复制。

## 七、协同接口

一个需求从哪来、到哪去：

```text
需求（谁在搜什么）
  ├─ Google / 英文 → hq-chuhai 选词 → 自有站页面 → 部署 → GSC 复盘
  └─ 中文平台      → hq-geo 选词   → 平台内容   → 分发 → 台账复盘
```

四条接口规则：

1. **内容方法单向流动。** hq-geo → hq-chuhai。反向不引用。
2. **事实可共用。** 一个产品的事实包两边都能读。格式由 hq-geo 定义。
3. **门禁各自跑。** hq-geo 跑 `run_quality_gate.py`，hq-chuhai 跑 `system/tests/run.sh`。
   两套门禁不合并，各管各的资产。
4. **一个项目只能有一个资产归属。** 跨身份的项目要写清两边的边界，见第八节。

## 八、双身份项目怎么写

有些目录同时是 hq-chuhai 的站和 hq-geo 的项目根。
这样的目录要在自己的 `CLAUDE.md` 里写清三件事：

1. 资产归谁（按第二节判据）
2. 哪部分纳入 hq-geo 系统，哪部分声明范围外
3. `output_baseline` 记的是哪一部分

**空的实例层不许 PASS。** 产出 0 对基准 0 不是合规，是漏记。
基线要么写真值，要么写明为什么是 0。
