# HQ Content Engine 设计基线

**状态：** 部分实现；GEO 能力包和内容路由已落地，三平台采集与物料生成待实现  
**版本：** 0.1  
**建立日期：** 2026-09-09  
**适用渠道：** 视频号、抖音、小红书、自有博客、指定新闻网站或行业媒体

## 一句话定义

HQ Content Engine 是一个由自然对话驱动的本地内容系统：Conan 只需说出一个尚未成形的想法，系统负责完成跨平台调研、关键词与用户问题抽样、选题推演、内容创作、物料生成、平台适配和发布前检查，最后停在公开发布之前，等待一次明确授权。

```text
想法
  → 三平台调研
  → 用户语言与关键词
  → 选题讨论和选择
  → 跨平台母稿
  → 文章成稿 / 视频制作简报 / 图片制作简报
  → 视频号 / 抖音 / 小红书 / 博客 / 指定媒体发布包
  → 硬规则预检
  → 等待点击发布
```

## 核心判断

1. 这不是给现有 GEO 项目“多加几个 Skill”，而是把项目边界升级为内容引擎；GEO 保留为其中一个研究与分发能力。
2. 关键词不是创作起点的唯一真相。它只证明“有人在用这种语言表达需求”，不能替代 Conan 的观点、经验和判断。
3. 三个平台的指数口径不可直接相加。系统保存各平台原始信号，再用平台内相对位置和跨平台复现度形成选题判断。
4. 所谓“好做法”应保存为带适用条件的策略模式，而不是僵化爆款模板。
5. 发布规则必须是有来源、有日期、会过期的动态事实。每次进入发布环节都要执行运行时预检。
6. 公共发布是不可逆外部动作。系统可以自动准备草稿、填写表单和生成预览，但必须由用户明确授权后才能公开发布。
7. 选题只是创作输入，不是创作结果。视频至少交付可执行制作简报，文章至少交付完整成稿，图片至少交付包含文案、构图、尺寸和事实引用的制作简报。

## 文档权威关系

- 本目录描述新的目标产品和迁移边界。
- 当前仓库已经实现什么，以实际 `SKILL.md`、Python 脚本和测试结果为准。

## 本轮未做

- 已实现项目级内容路由与 GEO 能力抽象；尚未实现三平台采集器、平台 renderer 或发布器。
- 没有代替用户登录抖音或视频号。
- 没有把任何内容公开发布到平台。
- 没有把尚未从当前官方发布界面核验的数字写成硬限制。
