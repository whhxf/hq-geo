# 本地创作工作台系统设计

**状态：** 部分实现；Slice 1 的本地工作台、视频画册导入与自动刷新已落地  
**界面技术约束：** 本地端口、Next.js + TypeScript、Shadcn UI  
**用户范围：** 第一版仅 Conan 单人使用

## 1. JTBD 与产品边界

当多个想法和选题同时推进时，Conan 需要随时看清每项内容已经完成什么、为何停下、AI 接下来做什么、此刻需要本人判断什么，从而把注意力留给观点、事实和发布决定。

工作台负责状态、记忆、证据、产物和行动入口；Codex 对话继续负责研究、讨论、创作和修改。第一版不做团队权限、复杂排期、社交数据大盘或通用项目管理。

## 2. 目标工作流

```text
想法收件
  → 三平台调研
  → 选题判断
  → 事实基础锁定
  → 母内容创作
  → 作者化检查
  → 三平台派生
  → 素材生成
  → 规则与质量预检
  → 等待发布授权
  → 已发布
```

### 事实基础锁定

创作前形成 `FactPack`，作为后续所有版本的强制上下文：

- 产品事实与能力边界；
- Conan 的原话、判断、经历与不确定性；
- 平台研究和用户原话；
- 可引用的案例、数字和来源；
- 禁止出现的承诺、未经验证能力和失效事实；
- 每条事实的来源、核验日期、适用范围与置信度。

事实分四层加载：全局品牌 → 产品 → 当前创意 → 当前选题。越具体的事实优先级越高；发生冲突时阻止创作继续，不由模型自行选择。

### 作者化检查

“去 AI 味”实现为可解释的作者化质量流程，详细规则见 `07-authorial-quality-system.md`：

1. 先做结构和清晰度编辑；
2. 使用 `dbs-ai-check` 诊断具体 AI 写作特征，保留原文位置和严重度；
3. 检查没有增加事实的程度副词、模糊修饰语和套话组合；
4. 只有明确 Conan 的表达意图、真实经历或语言偏好后才修改；
5. 修改后再次检查观点、事实和内容承诺是否漂移。

该阶段输出 `VoiceReview`，记录命中位置、处理决定、依据的作者上下文和修改前后差异。诊断通过不代表内容质量通过；事实、论证、平台表达分别检查。

## 3. 第一版信息架构

### A. 今日需要你

默认首页，只展示需要 Conan 行动的 1—5 项：选择选题、确认事实、补充经历、比较内容版本、授权发布。每项只给背景、一个明确问题和继续对话入口。

### B. 创意库

查看全部创意及阶段、更新时间、当前阻塞、下一步和目标平台。支持搜索和按状态筛选；阶段由状态文件决定，不通过拖拽随意修改。

### C. 创意工作区

单个创意的主页面：

- 顶部：题目、当前阶段、总体状态、下一步；
- 主区：当前阶段最重要的内容；
- 时间线：研究、决定、版本和测试记录；
- 侧区：事实基础、素材缺口、三平台产物和阻塞项；
- 固定入口：继续在 Codex 中讨论当前创意。

### D. 事实基础

按全局、产品、创意、选题查看事实。清晰区分 `verified`、`needs_confirmation`、`conflict`、`expired` 和 `prohibited_claim`。引用事实可以查看来源，不允许无痕覆盖。

### E. 发布准备

按视频号、抖音、小红书展示文案、素材、当前规则快照、质量测试与授权状态。只有所有阻断项清零，才出现“准备发布”；公开发布仍需明确授权。

## 4. 核心页面状态

| 状态 | 用户看到什么 | 系统下一步 |
|---|---|---|
| 空白 | 一句话输入创意，附一个真实示例 | 创建 IdeaBrief |
| AI 处理中 | 当前阶段、正在执行的任务、最后更新时间 | 后台监听文件变化 |
| 需要判断 | 一个具体问题、最少候选、影响说明 | 等待 Conan 决定 |
| 阻塞 | 缺少事实/素材/登录/规则及解除方式 | 不继续生成错误成品 |
| 阶段完成 | 完成证据、产物预览、下一阶段 | 自动推进或等待判断 |
| 测试失败 | 失败项、影响、建议修复动作 | 禁止进入发布状态 |
| 可发布 | 三平台包、规则时间、授权动作 | 等待明确授权 |

## 5. 数据与同步架构

```text
Codex 对话
   ↓ 原子写入
Markdown / JSON / JSONL 文件（唯一真源）
   ↓ 文件监听
本地 Next.js 服务
   ↓ Server-Sent Events
浏览器工作台自动刷新
```

- 不先引入数据库；现有 Markdown、JSON、CSV 继续作为可审计资产。
- 新的运行状态使用结构化 JSON，原始研究使用只追加 JSONL，长内容继续使用 Markdown。
- 写入采用临时文件加原子重命名，防止面板读到半个文件。
- 每次状态变化追加事件记录：时间、来源任务、旧状态、新状态、产物和原因。
- 页面通过 SSE 接收变更提示，再重新读取对应实体；断线后可自动重连和全量校准。
- 面板默认读取当前项目；其他工作区的素材通过显式路径引用或导入，不静默复制。

## 6. 最小数据对象

```text
IdeaBrief
ResearchRun
TopicCandidate
FactPack
CanonicalContent
VoiceReview
PlatformPackage
AssetManifest
PreflightResult
PublishJob
ActivityEvent
```

所有对象共享 `id`、`status`、`updated_at`、`source_thread_id`、`next_action`、`blocked_by` 和 `artifact_refs`，保证对话与面板使用同一状态语言。

## 7. Shadcn UI 使用原则

优先直接使用 `Sidebar`、`Breadcrumb`、`Tabs`、`Table`、`Badge`、`Progress`、`Sheet`、`Command`、`AlertDialog`、`Tooltip`、`Skeleton` 和表单组件。只做少量主题变量和布局组合，不自研基础组件。

避免把所有对象做成卡片、避免大型仪表盘数字、避免装饰性图表。进度用明确阶段和文字说明表达；数字只在能指导下一步时展示。

## 8. MVP 实施切片

### Slice 1：只读状态投影

- 本地 Next.js + Shadcn UI 项目；
- “今日需要你”、创意库、创意详情三页；
- 读取一个示例 IdeaBrief 与状态文件；
- 监听 Codex 写入并自动刷新；
- 显示阶段、阻塞、下一步、事实和产物链接。

验收：在 Codex 对话修改一个创意状态后，不手动刷新即可在面板看到正确变化。

**实现状态：已实现。** 当前已导入视频画册长期选题 43 条、广交会专题 48 条；`G1-02` 已进入事实锁定。工作台运行在 `http://127.0.0.1:3210`，SSE 文件变化验证通过。

### Slice 2：判断回写

- 在面板选择选题、确认/驳回事实、选择内容版本；
- 决定写回文件并追加事件；
- Codex 下一次对话能读取决定继续工作。

### Slice 3：创作质量与发布准备

- FactPack、作者化检查、三平台包和预检页面；
- 接入统一测试报告；
- 阻断项未清零时不显示发布就绪。

## 9. 测试策略

- 单元测试：状态计算、事实优先级、冲突和下一步推导；
- 契约测试：所有已实现阶段都有 schema、测试和界面映射；
- 集成测试：Codex 写文件 → 监听 → 页面更新；
- 工作流测试：创建想法 → 选择选题 → 锁定事实 → 创作 → 作者化 → 三平台包；
- 反向测试：删除或回退功能后，旧入口和错误状态不会残留；
- 发布门禁：事实冲突、规则过期、测试失败或缺少授权时无法进入可发布状态。

这些测试接入现有 `test/run_quality_gate.py`，新增界面功能不能以人工浏览代替自动验证。

## 10. 暂不实现

- 多用户、角色和权限；
- 拖拽式自由工作流；
- 内容日历和团队任务；
- 平台表现数据大盘；
- 内嵌完整 Codex 聊天客户端；
- 自动公开发布。
