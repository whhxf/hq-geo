# 作者化质量系统：从 AI 痕迹诊断到 Conan 表达

**状态：** 研究基线，待实现  
**调研日期：** 2026-09-09  
**适用内容：** 视频号、抖音、小红书的口播、标题、正文与字幕

## 1. 结论

系统不采用“AI 检测分数 → 自动洗稿”的路径。成熟做法的共同部分是：先保证内容具体、清楚、有作者事实，再识别重复的机器化模式，最后做最小修改并核对观点和事实是否漂移。

“少讲副词”应收窄为：

> 减少没有增加时间、范围、否定、程度或证据含义的副词；尤其检查用来制造气势、确定性和专业感的程度词与模糊修饰语。保留会改变事实条件的副词。

因此它是高价值诊断项，不是“副词越少越像人”的评分指标。

## 2. 已发现的可复用方法

### 项目已有 Skill

| 能力 | 可复用部分 | 局限 |
|---|---|---|
| `dbs-ai-check` | 22 类 AI 写作特征；按原文位置诊断；区分体裁；先问作者意图再改 | 默认只诊断，不能单独完成结构、事实和最终改写 |
| `bmad-editorial-review-structure` | 先处理删减、重排、信息密度和阅读路径 | 保护内容观点，不判断观点是否真实或独特 |
| `bmad-editorial-review-prose` | 最小干预；逐句修复清晰度；允许项目风格指南覆盖 | 目标是清楚，不专门识别 AI 痕迹 |

### 外部成熟方案

开源 [blader/humanizer](https://github.com/blader/humanizer) 在调研时约有 45.6k GitHub stars，整理了 25 类模式，包括 “Not X but Y”、戏剧化短句、强行三段式、堆叠限定词、AI 高频词、夸大意义、借用模糊权威、装饰性标题和聊天残留。值得复用的重点有：

- 不把原稿结构当作不可改变；
- 事实细节只能来自来源或作者，缺少就询问；
- 可以用作者样本匹配节奏、词汇、标点和有意保留的习惯；
- 初稿改写后再次扫描，并检查原始主张是否被改变。

这套 Skill 与 `dbs-ai-check` 重叠较多。第一版不直接安装，先把互补模式抽象进项目能力，避免两个规则库独立演化。

长期编辑规范也支持“删掉无作用修饰语、使用具体动作”的方向：美国国家档案馆的 [Principles of Clear Writing](https://www.archives.gov/federal-register/write/legal-docs/clear-writing.html) 强调主动语态、简短句子、具体而熟悉的词；FAO 的 [Writing well](https://openknowledge.fao.org/server/api/core/bitstreams/1fcf6527-d70a-423c-8483-a741bb1c3794/content/writing-well.html) 明确建议避免不必要或含义模糊的副词和强调词，并替换不精确动词。

AI 文本检测器不能作为作者化门禁。Stanford HAI 汇总的研究显示，多种检测器会对非英语母语者产生明显误判，也容易通过改写规避。因此系统只报告可解释的文本特征，不输出“人类概率”或以检测器分数判定质量。[Stanford HAI](https://hai.stanford.edu/news/ai-detectors-biased-against-non-native-english-writers)

## 3. 作者化流水线

```text
事实与观点锁定
  → 结构编辑
  → 清晰度编辑
  → AI 痕迹诊断
  → Conan 语料与意图校准
  → 最小改写
  → 事实/观点差异检查
  → 口播朗读检查
```

### Gate A：内容必须有作者来源

至少具备一项：Conan 原话、真实经历、明确判断、产品演示、已核验事实、承认的不确定性。全部来自模型补全时，作者化状态不得通过。

### Gate B：结构先于措辞

先删除重复论点、虚构反驳、无用总结和为了完整而凑出的段落。结构未解决时，不进行同义词替换式“润色”。

### Gate C：副词与模糊修饰语检查

自动标出但不自动删除：

- 程度堆叠：`非常`、`极其`、`十分`、`尤其`、`真正`、`更加`；
- 无证据的效果词：`显著`、`有效`、`全面`、`充分`、`精准`；
- 套话组合：`持续提升`、`深度赋能`、`全面覆盖`、`有效解决`、`充分发挥`、`不断优化`；
- 重复限定：同一句或相邻句连续使用多个“可能、通常、相对、一定程度上”。

每个命中只问三个问题：删掉后含义是否变化；能否换成具体动作；能否提供事实或条件。否定词、时间词、范围词和真实不确定性不得为了降密度删除。

### Gate D：模式诊断

合并 `dbs-ai-check` 与 Humanizer 的互补模式，优先检查：

- 高频“不是 X，而是 Y”；
- 每段都收束成金句；
- 固定三段式和匀速排比；
- 替读者提出一个没人说过的蠢问题；
- “本质上、归根结底”等无依据升维；
- 开头固定“钩子—痛点—承诺”；
- 句长和节奏过度均匀；
- 模糊专家、行业数据和借来的权威；
- “值得注意的是、在当今时代、希望对你有帮助”等聊天残留。

体裁决定阈值：短视频允许高密度短句和金句；小红书清单允许结构重复；视频号观点稿更重视自然停顿与真实犹豫。单一模式不直接判失败。

### Gate E：作者样本校准

建立 Conan 语料库，保存来源、日期、场景和是否本人认可。系统提取偏好，不模仿表面口头禅：

- 常用句长与停顿；
- 习惯使用的词和明确拒绝的词；
- 怎样表达不确定；
- 怎样讲经历、反例和产品；
- 哪些观点是长期立场；
- 哪些“毛边”是本人有意保留。

没有合适样本时，系统应请求一段原话或保留中性表达，不虚构“Conan 风格”。

### Gate F：改写后防漂移

改写前后逐项对比：核心判断、数字、专有名词、因果、适用条件、否定和承诺。任一变化未得到事实依据时回退或标记待确认。

## 4. 工作台界面

作者化检查显示可解释的问题列表，不显示总分仪表盘：

```text
作者化检查：需要处理 4 处

1. “全面提升客户的理解效率”
   问题：全面、提升、效率都没有可观察对象
   建议：说明客户少做了哪个动作，或补真实证据
   [接受修改] [保留原文] [告诉 AI 我的说法]
```

顶部只显示三种状态：`待检查`、`需要 Conan`、`已核验`。每次处理记录原文、建议、决定、修改后文本和依据的作者上下文。

## 5. 测试与验收

- 固定样本集：真实 Conan 文本、明显 AI 文本、优秀第三方文本和容易误伤的短视频文本；
- 单条规则测试：副词、排比、假权威、聊天残留等命中与不命中样例；
- 体裁误伤测试：相同结构在不同平台体裁下结果不同；
- 防漂移测试：数字、否定、条件和产品能力不可在改写中变化；
- 作者盲评：原稿和修改稿隐藏来源，由 Conan 选择更像自己且更愿意发布的版本；
- 失败标准：只有“更不像 AI”但观点变弱、事实变化、口播变差或 Conan 不愿发布，均判失败。

副词数量只作为诊断统计，不设统一通过阈值。系统真正优化的是具体性、作者所有权和发布意愿。

## 6. 建议实现顺序

1. 先建立 Conan 认可语料和禁用表达；
2. 把 `dbs-ai-check` 接成只读诊断；
3. 增加副词/模糊修饰语的确定性扫描器；
4. 接入结构编辑和清晰度编辑；
5. 实现改写前后事实差异检查；
6. 用盲评结果调整规则，暂不训练通用“人味评分”。
