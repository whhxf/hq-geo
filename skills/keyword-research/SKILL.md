# 关键词研究

## 目的

**把「我觉得这个方向行」变成「有证据说明有人在用这种话表达这个需求」。**

```
想法 → 定种子词表 → 词汇延展（小红书聚光 + 广点通） → **你确认关键词** → SERP 研究（小红书 / 抖音 / AI 平台）
     → 把 SERP 汇总给你 → 讨论选题 → 登记 → sourcing → brief → 内容
```

它**不产出事实**。事实走 `skills/sourcing/` 的检索路径，进事实包。
这里产出的是**需求信号**：谁在搜什么、用什么话搜、竞争多激烈、他们真正要完成什么任务。

## 开始前

完整读取：

- `capabilities/keyword-research/contracts/research-record.schema.json`
- `capabilities/keyword-research/contracts/demand-cluster.schema.json`
- `capabilities/keyword-research/channels/README.md`
- `capabilities/topic-registry/contracts/topic.schema.json`

**先读 `research/library/README.md`——这是第一件事，不是可选的。**

**库里是这个项目已经花过钱采回来的结论。** 一次 SERP 研究是 每个词 × 每个平台 各采一次，
重跑一遍就是重付一遍。**按「覆盖的词」列搜你要研究的词，不要按主题名猜**——
主题名和词的对应不是一对一的（`AI客服` 的结论可能住在 `AI数字员工.md` 里）。

同一个项目根下，同样的索引也在 `CLAUDE.md` 末尾那块——**那是每次会话自动加载的**，
所以多数时候你已经看过了。但**换设备、克隆仓库、或上下文被压缩之后要自己读一次**。

再读项目根的 `data/ideas/`、`research/`、`topics/`——**看这个想法有没有已经做过的调研**，
有就接着做，不重开一轮。

## 站 1：定种子词表

从一个想法出发，定**一张种子词表**，不是定一个核心词。

**为什么是复数**：聚类的目的就是「把不同的词合起来」。只定一个词，
等于先假设了自己知道这个词长什么样——而调研要回答的恰恰是「用户到底怎么叫它」。
Ahrefs 的说法是「别在挑词上纠结」：挑错的成本远低于漏掉的成本，
**多定几个，让数据来分。**

> **这一轮要回答的是什么问题？**

- 想知道「有没有人在关心这件事」→ 种子词用**用户会怎么叫它**，不用你内部的叫法
- 想知道「他们到底卡在哪一步」→ 种子词用**任务词**（怎么搭、多少钱、能不能替代）

**3–8 个**是合适的量：够覆盖叫法的变体，又不至于让采集成本失控。

种子词歪了，后面全歪。**定完先给用户看一眼再往下走。**

## 站 2：词汇延展——在小红书和广点通上找词

**这一站只回答一件事：这些词各有多大的量、多难做、广告主愿意出多少钱。**

**只有官方商业工具能给量。** 内容平台（小红书搜索页、抖音）和 AI 平台（豆包、DeepSeek、千问）
都不给搜索量——它们只能回答「谁排在前面」「AI 引用了谁」。量级这一层，只有商业工具能填。

**两个都要跑**（`xhs-spotlight` + `gdt-bidword`）。只跑一个生态，
等于先假设了两个生态的需求一样——**那是假设，不是测量。**

**只选 verified 的。** `unverified` 的渠道进去是试错，不是采集——那种情况明确说「这个渠道我还没跑通过，
这次要去试，可能拿不到东西」，不要假装有把握。

一个渠道能回答的问题不一样，站 4 选渠道时照这张表：

| 想知道 | 去哪 |
|---|---|
| 有多少人在搜、竞争多激烈、广告主愿出多少钱 | 官方商业工具（`official_commercial`） |
| 用户自己怎么描述这个问题 | 原生内容（`native_content`）：搜索建议、笔记、评论 |
| 这个需求在别的生态里热不热 | 代理信号（`proxy`）——**只能当参考，不能当目标指标** |

**一次跑一个渠道，跑完落盘再跑下一个。** 渠道并行会让记录串味。

### 采集纪律

按渠道文件的「采集步骤」走。**每个渠道文件里写了该用哪个浏览器工具，以它为准。**

**不要按「要不要登录」推工具**——登录态在哪个浏览器里是**实测**出来的，各渠道不同：
聚光（`xhs-spotlight`）和广点通（`gdt-bidword`）走 `ego-browser`；
小红书搜索页（`xhs-serp`）和抖音（`douyin-search`）的登录态在 `web-access` 那边
（ego-browser 的 profile 没有小红书登录态，用它会被挡在登录页）。
总体原则见 `AGENTS.md` 第 100 行：优先 `ego-browser`，跑不通或场景不适用时退回。

**渠道文件里的「已知陷阱」是实测出来的，不是模板。** 尤其是速率限制——
小红书连续快搜会掉登录态，看到 0 条先检查有没有登录墙，**不要把风控当成「这个词没有内容」**。

**每读一个页签，立刻落盘。** 攒到最后会丢。

落盘到 `research/raw/<date>-<channel>-<slug>.json`，按 `research-record.schema.json` 写。

**不要在真实网站上用 `keyboard.paste` 往表单里填文本。** 它在某些站点上会粘
**用户剪贴板里的实际内容**，不是你的实参，而且不报错（2026-09-29 在 `ad.qq.com` 实测）。
填表一律用 `page.fill()` 或 `page.keyboard.insertText()`——它们在页面内直接设值，不经过剪贴板。

三条纪律：

1. **平台给什么记什么，不改写。** 竞争指数写「高」就记「高」，不换算成数字。
2. **噪音词保留说明。** 平台返回的无关词进 `noise`，写清为什么无关——
   丢掉的话，下次看到同一个词还要重新判断一遍。
3. **口径问题当场记进 `notes`。** 比如「用户路径里的占比是路径内占比，不是全站占比」——
   这类现场发现比任何文档都准。

## 站 3：归一化成候选词表

**先聚好再给用户看，不是把散词扔给他。** 一屏两百个词他没法判断；
按「用户要完成什么任务」分好组，他一眼就知道哪几组是自己的生意。

**分三级聚，能算的不要猜。**

### 第一级：词面归一（零成本，可复核）

大小写、空格、分隔符的变体先合并。纯规则，没有判断。

### 第二级：SERP 重叠（每个词一次搜索，可复算）

两个词分别搜一次，取前排内容指纹算 Jaccard：

```
J(A, B) = |A ∩ B| / |A ∪ B|
```

**指纹必须用平台的内容 ID**（小红书用 `note_id`），不能用标题——标题会重复、会被改。

判据（阈值是 2026-09-29 实测的，不是照搬 Ahrefs，
见 `capabilities/keyword-research/methods/serp-overlap-clustering.md`）：

| Jaccard | 动作 |
|---|---|
| **≥ 0.15** | 合簇（强证据） |
| 0.08–0.15 | 边缘，读内容再定 |
| **< 0.08** | **不能作为合簇证据**，回到用户任务判断——但必须排除「内容稀缺」 |

**两条最容易用反的：**

1. **高重叠是「该合簇」的证据，低重叠不是「该拆簇」的证据。**
   一篇内容可以同时被多个 SERP 召回。
2. **跨簇高重叠有两种含义**：同一个任务分错了（→ 合簇），
   或连续的两个任务、一篇内容能同时答（→ **内容可复用，不必合簇**）。

**低重叠 + 前排主题相同 = 内容稀缺，不是不同意图。** 这是机会信号（有人搜、没人做），
不是分簇依据。

**数字之后必须读内容。这一步不能省，也不能自动化。**

### 第三级：用户任务（兜底）

SERP 采不到时（渠道不可用、内容太少、撞风控），回到判断：
**两个词能不能用同一篇内容回答？**

这一级不可复核，所以**必须在 `clustering_basis` 里写明是 `task_inference`**——
让下游知道这个簇没有测量支撑。

### 必填：`clustering_basis`

每个簇都要写清**凭什么聚出来的**：`surface_norm` / `serp_overlap` / `task_inference`。
写了 `serp_overlap` 就必须带 `serp_evidence`——**证据支持或反对都要记**。
采到反证却不写，等于只记对自己有利的。

落盘到 `research/normalized/<date>-<slug>.clusters.json`，按 `demand-cluster.schema.json` 写。

**这一步最容易犯的错是编词。** 校验器会逐词核对——`representative_keywords` 里的每个词，
必须能在 `source_records` 里找到。**代表词不是你想出来的，是从记录里挑出来的。**

**推断词单独放。** 由需求簇推导出来、但平台还没给数据的词，进 `inferred_keywords`，
写清凭什么推出来、要去哪里验证。**它们不能混进代表词**——混进去就是把推断当证据用。

### 闸门：交给用户确认

**落盘不等于往下走。** 把候选词表给用户，**等他选定，才做 SERP。**

给用户看三样：

1. **按簇分组的候选词**——每簇一句话说清「谁在什么场景下要完成什么」，附量级 / 竞争 / 出价
2. **排除项**——看过但排除的，写清为什么。**排除项是判断的一部分，不是没看见**
3. **你要选的是词，不是簇**——一簇里可以有你不要的词，也可以跨簇选

**没有用户确认就去做 SERP，等于替他决定了要研究哪些词。**

## 站 4：SERP 研究

**只研究用户确认过的词。** SERP 是这套流程里最贵的一步——每个词 × 每个平台各一次采集，
花在没被选中的词上是纯浪费。

**它回答的是站 2 答不了的问题：这些词的前排内容是不是同一批。**
商业工具说「有多少人在搜」，SERP 说「搜的时候看到的是什么」。**两件事，缺一个都做不了判断。**

### 用哪些平台

| 平台 | 渠道 / 能力 | 拿什么 |
|---|---|---|
| 小红书 | `xhs-serp` | 前排笔记，指纹用 `note_id` |
| 抖音 | `douyin-search` | 前排视频；拿不到内容 ID 时只能用标题，**这是它的已知弱点** |
| AI 平台（豆包 / DeepSeek / 千问） | **调 `skills/geo-research/`** | 不是排名，是「AI 说了什么、它认谁当信源」 |

**AI 平台和内容平台返回的不是同一种东西**，但**不在这里另建一套记录格式——复用 `geo-research` 的**。
同一件事有两套格式，下游不知道该信哪个。

**一次跑一个渠道。** 采集纪律同站 2。

### 判据

沿用 `capabilities/keyword-research/methods/serp-overlap-clustering.md` 的阈值，**不重新发明**：

| Jaccard | 动作 |
|---|---|
| **≥ 0.15** | 合簇（强证据） |
| 0.08–0.15 | 边缘，读内容再定 |
| **< 0.08** | **不能作为合簇证据**，回到用户任务判断——但必须排除「内容稀缺」 |

**指纹必须用平台的内容 ID**，不能用标题——标题会重复、会被改。

**数字之后必须读内容。这一步不能省，也不能自动化。**

### 回填 `clustering_basis`

站 3 落盘时 SERP 还没跑，所以那一版只可能写 `surface_norm` 或 `task_inference`。
**站 4 跑完必须回头更新 `research/normalized/` 里对应的簇**：

- 两个词 SERP 重叠 **≥ 0.15** → `clustering_basis` 改成 `serp_overlap`，补 `serp_evidence`
- 重叠 **< 0.08** → **保持原依据**，但同样在 `serp_evidence` 里记下这次测量
- **边缘区间** → 读内容再定，并在 `judgment` 里写明读了什么

**证据支持或反对都要记。** 采到反证却不写，等于只记对自己有利的。

**不补等于放弃了这一轮最贵的证据。** 校验器拦得住「写了 `serp_overlap` 却没有 `serp_evidence`」，
但拦不住「明明测了却仍写着 `task_inference`」——**那一半只能靠这一步的纪律。**

## 站 5：把 SERP 汇总给用户

**给原始结果，不给摘要。** 用户要看的是「搜的时候到底看到什么」，
转述会把判断依据过滤掉——**那正是他要看的东西**。

**但要有结构，不能倒一屏给他。** 每个词一个平台十几条，五六个平台乘下来几百条，
倒出去就是让他自己干一遍采集的活。

- **按平台分节，平台内按词分组**
- 每组给 **TOP 5**：标题 / 作者（或来源） / 链接 / 内容 ID
- **量级和判断放前面，原始结果放后面**——先给结论，细节按需展开
- 用户指哪条，再展开哪条

**只汇总，不替他下结论。** 这一步是让他看到原本看不到的东西，不是告诉他该怎么想。

## 站 6：讨论选题，登记

**这一站不能省。** 需求簇是机器聚出来的，「要不要做、先做哪个」只有用户能定。

**到这一步你手上已经有：站 3 他确认过的词、站 5 汇总的 SERP。**
讨论基于这两样，不是重新讲一遍数据。

给用户看三样：

1. **需求簇**——每个簇一句话说清「谁在什么场景下要完成什么」
2. **排除项**——看过但排除的，写清为什么。**排除项是判断的一部分，不是没看见**
3. **你的判断**——哪个簇最值得做、为什么、风险在哪

然后问**一个问题**：

> 「这几条里，哪一条你手上有别人没有的东西可说？」

**这一问是分水岭。** 答得上来的，才可能变成真选题；答不上来的，做出来也是同质化内容。

### 登记

讨论完产出**备选选题**，写进 `topics/<idea>/topics.json`，按 `topic-registry` 的契约。

**选题必须能回答五问**（见 `capabilities/topic-registry/`）：

1. 谁在什么场景下遇到什么问题？
2. 现有解释或做法哪里失效？
3. 你有什么不同判断或可展示证据？
4. 内容承诺是什么，看完能得到什么？
5. **这个承诺如何被证伪？**

**答不上第 5 问的不是选题，是想法。** 想法留在 `data/ideas/`，不进选题记录。

新登记的选题 `state` 是 `candidate`。**选定哪条由用户说，不由系统推荐。**

## 收尾

### 入档：可复用的结论进 `research/library/`

**这一轮花掉的 token、时间和采集成本，只有写进库里才留得下。** 结论只留在对话里，
下一轮从零开始——**那等于这次白花。**

写 `research/library/<主题>.md`（主题用这一轮的核心词），**一个主题一个文件，文件名不带日期**。

**两条都答「是」才进库：半年后还成立吗？别的选题会用到吗？**
数得出来的例子：跨平台需求强度差异、一个簇被第二个平台独立复现、某类词有没有量的判断。
**不进**：这一轮的簇列表（那是 `normalized/` 的事）、今天谁排第几（快照不是结论）、没跑通的报错。

每条结论**三样缺一不可**：**数字 / 口径 / 出处**（指到 `research/raw/` 的具体文件 + 采集日期）。
**没有口径的数字是错的，不是不完整的**——它被引到内容里就变成跨平台加总，`AGENTS.md` 第 61 行是硬线。

结论被推翻时**划掉留痕，不要删**——「这个假设是错的」本身就是参考资料。
完整格式和理由见 `capabilities/keyword-research/methods/research-library.md`。

**写完库文件必须重建索引，否则这一轮等于没入档**：

```bash
python3 capabilities/keyword-research/scripts/library_index.py --project <项目根>
```

**索引是派生的，不要手改。** `covers`（覆盖的词）和 `summary` 写在库文件的 front matter 里，
脚本从那里生成两处索引——`research/library/README.md` 和**项目 `CLAUDE.md` 里那块
每次会话自动加载的索引**。**漂移的索引比没有更糟**：它会让人以为「库里就这些」。
校验器会逐字比对，忘了重生成门禁就红。

### 给用户三样

1. **这次调研发现了什么**——一句话，不是复述表格
2. **哪些还不能用**——推断词、没跑通的渠道、未知的量级
3. **下一步**——选定某条就进 `skills/sourcing/` 立 brief；不选就把选题留在记录里

## 边界

- **不产出事实。** 平台信号不是事实，不能进事实包。要事实走 `sourcing` 的检索路径。
- **不做跨平台加总。** 小红书的 370 和抖音的 370 不是一回事。`AGENTS.md` 第 61 行是硬线。
- **不把推断当证据。** 推出来的词标清楚是推出来的。
- **不替用户选选题。** 系统给证据和判断，选定哪条是用户的决定。
- **不跳过站 6。** 没有讨论就直接登记的选题，五问里至少三问答不上来。
- **不跳过站 3 的闸门。** 用户没确认关键词就做 SERP，研究的是系统挑的词，不是他要的词。
- **不把结论只留在对话里。** 没入档的调研，下一轮要重花一次钱——**最贵的一步重复付两次。**

## 和相邻能力的分工

| 谁 | 回答什么 |
|---|---|
| **本 skill** | 平台上真实的人在搜什么、用什么话、要完成什么任务 |
| `skills/geo-research/` | AI 搜索里的问题模型：Query Fan-Out、竞品占位、内容空白。**站 4 的 AI 平台采集直接调它，不另建记录格式** |
| `skills/sourcing/` 检索路径 | **这条内容里的事实从哪来**——一手来源、三级定级 |
| `capabilities/topic-registry/` | 选题的登记与准入（五问） |
