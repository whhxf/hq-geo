# 需求卡片法

**把「一堆关键词」变成「几张能排序、能接页面、能验收的卡」。**

需求簇回答「哪些词是一件事」。卡片回答「这件事该用什么页面接、先做哪张、做完怎么验收」。
中间隔着的这一段，就是这份方法卡。

来源：Conan 的「需求卡片法」操作手册（2026-10-16）。
**判据和实测数据来自同日一次外贸方向的完整落地**，不是照搬的。

---

## 一、为什么需要它

关键词研究现在的产物停在需求簇。簇能回答「这几个词是不是同一个任务」，
回答不了接下来三个问题：

| 问题 | 没有卡片时会怎样 |
|---|---|
| 这个需求该用什么页面接？ | 所有需求都去做博客，形式单一 |
| 几十张卡先做哪张？ | 按搜索量排，量大的先做——**而量大的常是求职场** |
| 做完怎么知道有没有用？ | 只看排名，不看 CTA 和成交 |

**卡片是研究结果进入生产的最小单位。** 没有它，研究结果停在表格里。

---

## 二、一张卡装什么

| 分组 | 字段 | 说明 |
|---|---|---|
| 需求侧 | 需求名称 | **写客户的问题，不写产品词** |
| | 用户是谁 | 老板 / 业务员 / 小团队——要具体到人数 |
| | 发生场景 | 哪个渠道、什么时刻 |
| | 真实痛点 | 他现在烦的是什么 |
| | 想要结果 | 他要变成什么样 |
| 词侧 | 关键词簇 | 需求下面的所有说法，一行一个 |
| | 搜索意图 | 了解 / 问题 / 找方案 / 购买 |
| 生产侧 | 承接页面 | 产品页 / 场景页 / 解决方案页 / 对比页 / 教程页 / 案例页 |
| | 页面逻辑 | 认 → 痛 → 解 → 信 → 动 |
| | CTA | 下一步做什么 |
| | 优先级 | 见第五节 |
| 上线后 | 上线数据 | 展现 → 点击 → CTA → 咨询 → 成交 |

**「上线数据」这一行是卡片和选题的区别。** 选题在交付时结束，卡片在交付后才开始收数。
一张卡不是做完就结束，是持续更新。

### 需求侧怎么写

判断标准只有一条：**能不能还原成客户的一句话「我现在烦的是……」**。

| 差的写法 | 好的写法 |
|---|---|
| AI 自动回复 | 小型团队收到社媒询盘后，希望 AI 先沟通和筛选，让业务员只跟高意向客户 |

差的写法是产品词，它已经预设了答案。好的写法把「谁 + 场景 + 痛点 + 结果」四样都补齐了。

### 页面逻辑五问

| 字 | 问的是 |
|---|---|
| 认 | 这是给谁的？ |
| 痛 | 他现在的问题是什么？ |
| 解 | 你怎么解决？ |
| 信 | 为什么相信你？ |
| 动 | 下一步做什么？ |

## 三、从词到卡的三步

**顺序不能反。**

1. **先写需求，不先写关键词。** 先回答「这个客户此刻想解决什么」。
2. **补齐「谁 + 场景 + 痛点 + 结果」。** 四样缺一，需求就还是模糊的。
3. **现在才问：这个人在搜索框里会怎么表达这个问题？** 词挂在需求下面，不挂在产品下面。

**关键词不是需求本身，是需求在搜索框里的不同说法。**

---

## 四、搜索意图分四层

| 层 | 例子 | 离成交 |
|---|---|---|
| 了解 | 什么是 X | 最远 |
| 问题 | X 太多怎么处理 | 中 |
| 找方案 | X 自动回复工具 | 近 |
| 购买 | X 软件价格 / X alternative | 最近 |

**这四层是第五节横轴的来源。**

## 五、多张卡怎么排序：四象限

### 两根轴

| 轴 | 含义 | 判据 | 数据来源 |
|---|---|---|---|
| 横轴 | 离成交的距离 | 词性（四层）+ **市场出价** | 平台官方商业工具 |
| 纵轴 | 内容供给的拥挤度 | SERP 前排是谁在承接 | 原生内容渠道 |

**为什么出价能当横轴判据。** 出价是广告主的竞价意愿。
2026-10-16 实测同一批词里：`外贸电话沟通话术` 出价 **12.82 元**、`外贸聊天` **9.08 元**；
而 `外贸跟单` 只有 **0.30 元**——**指数却是它最高（26,857）**。
指数高但出价低，说明搜的人是找工作的个人，不是买软件的企业。**出价区分的是人群，指数区分不了。**

### 为什么不用搜索指数当纵轴

**指数高不等于能做。** 同一批数据里 `外贸业务员` 指数 **46,618**，
是全部词里最大的，但它是**求职场**——人群、意图、付费方三者全不同。

### 四个格子

| 象限 | 位置 | 策略 | 判断动作 |
|---|---|---|---|
| **I 成交位** | 高意图 · 供给空 | **先做** | 看前排有没有从买方视角讲这件事的 |
| **II 红海位** | 高意图 · 供给挤 | 带独有判断才做 | 看前排结论有没有被人先说过 |
| **III 认知位** | 低意图 · 供给空 | 蓄水 | 看量级够不够撑独立页 |
| **IV 噪音位** | 低意图 · 供给挤 | 不做 | 看人群对不对 |

**象限 II 的关键动作是「看结论有没有被人先说过」，不是「看有多少人写」。**
2026-10-16 实测：半夜询盘这一簇出价最高（9.08 / 12.82 元），
但已有一家竞品先发布了「AI 不该先报价」的判断。**出价高但结论被占，就是象限 II，不是象限 I。**

### 分项打分

四象限定位置，位置里面再排序。四个分项，各 1–5 分：

```
优先级 ≈ 商业意图 × 产品匹配度 × 搜索机会 ÷ 竞争难度
```

**不需要数学精确。** 它的作用是把「我觉得该做」变成四个能对着数据回答的问题。

## 六、和现有对象怎么对接

```
关键词研究 ──→ 需求簇 ──→ 需求卡片 ──→ 选题五问 ──→ brief ──→ 内容
                  │            │            │
              哪些词是一件事  该用什么页接   做不做
```

| 对象 | 回答什么 | 契约在哪 |
|---|---|---|
| 需求簇 | 哪些词是同一个任务 | `contracts/demand-cluster.schema.json` |
| **需求卡片** | 该用什么页面接、先做哪张 | **本方法卡。不设契约** |
| 选题 | 做不做 | `capabilities/topic-registry/`（五问） |
| brief | 怎么写 | `capabilities/content-production/` |

**卡片不设契约，这是有意的。** 它是一层草稿——把「这个需求值得做吗」拆成能对着数据回答的几问，
答完才进选题五问。**加契约会把草稿变成流程，草稿就不敢改了。**

**卡片不能替代选题五问。** 五问里的第 5 问（怎么被证伪）卡片答不了，
它是选题里唯一真正属于作者的部分。**卡片答「值不值得做」，五问答「做完对不对」。**

### 一条纪律：卡片进选题前先过产品方向表

2026-10-14 实测教训：四条选题进了 `topics.json`，其中两条被置 `dropped`，
理由都不在关键词数据里——它们**不在产品官方的内容方向内**。

**量级大不等于该写。** 同一轮里量级最大的那一簇（3,363）被放弃，
因为产品只覆盖其中一段，写全了就是越界承诺。

**动作**：卡片池做完之后，先逐条对着产品官方方向表筛一遍，再决定哪几张进 `topics.json`。

## 七、实测（2026-10-16，外贸方向）

### 数据规模

| 渠道 | 记录数 | 性质 |
|---|---|---|
| 小红书聚光（两轮） | 3,255 | official_commercial |
| 广点通搜一搜 | 360 | official_commercial |
| 小红书 SERP | 105 | native_content |
| 抖音 SERP | 99 | native_content |

产出 **7 张卡**，落在四个格子里。

### 三条被数据改掉的判断

**一、「接待」这个词在两个平台都指线下看厂。**
小红书前排是展会记住人、来厂参观英文；抖音是沉浸式接待、韩国客户探厂。
**前排 20 条里没有一条讲线上的第一次接触。**
→ 上一轮留的问题「这个词是缺口还是没需求」，答案只能是 SERP，不是指数。**是缺口。**

**二、「AI 工具」这个词在两个平台都指开发客户。**
抖音前排是自动找客户、领英找客户、Codex 开发客户；小红书是 AI 开发分析客户。
**没有一条讲 AI 接询盘。**
→ 结论：**这个词已经被「找客户」占据。** 要用它，必须先和「找客户」区分开。

**三、「客户不回消息」是最挤的一格。**
两个平台前排全是话术。进这一格必须换角度，写话术一定被淹掉。

### 一条跨渠道的发现

微信搜一搜的外贸 AI 词**月均搜索量全部 ≤20**（最高 20），
而同一工具下通用方向的词是 100 / 40。
→ **微信生态在这个品类里不是搜索获客场。** 这条只有把两个方向都采了才看得出来。

## 八、已知边界

- **纵轴的判据是定性的，没有阈值。** 「供给挤不挤」靠读前排，靠人判断。
  这和 `serp-overlap-clustering.md` 不一样——那边有可复算的 Jaccard 阈值。
  **不要把这一格当成测量值用。**
- **出价只在平台内有效。** 跨平台不能比较，也不能把「出价高」直接读成「商业价值高」——
  同一批数据里通用获客词的出价远高于行业词，**那是代运营生意的价格，不是本品的价格**。
- **供给拥挤度只看前排，没翻页。** 也没跑「最新」「最热」等排序。
  要判断某张卡的真实竞争度，需要按排序方式各采一次。
- **卡片答不了「产品能不能接」。** 产品覆盖到哪一段要产品侧确认，不是关键词研究能回答的。
- **这张卡没有校验器。** 判据只靠人读。按宪法第 8 条，等它被真实用过第三次再决定要不要加断言。

## 九、和外部方法的关系

「需求先行、关键词后挂」这条，和 `ahrefs-keyword-research.md` 的站 1 是同向的——
Ahrefs 也要求先列种子词表而不是定一个核心词。

**本方法卡多出来的两样，是 Ahrefs 没有的：**

| 多出来的 | 为什么需要 |
|---|---|
| **四象限坐标** | Ahrefs 给的是「这个词值不值得做」，本系统要回答「这几张卡先做哪张」 |
| **上线数据回填** | 内容获客的终点是成交，不是排名。**不回填，就无法知道哪一种需求最容易成交** |

**评分公式是自建的，不是引进的。** 外部那套「搜索量 × 0.35 + 竞争低 × 0.40 + 商业价值 × 0.25」
是建站排名逻辑，竞争低占最高权重。**内容获客的逻辑相反**——
竞争高、出价高说明商业意图强，正是该做的地方。见 `../README.md` 的「和外部方法的关系」。
