# 渠道适配器

**关键词研究是组合技能，不是一条流水线。** 同一个问题，在小红书、抖音、微信里要用不同的方式问，
拿回来的数据口径也各不相同。**每个渠道一个文件，加渠道就是加文件，渠道改版就是改文件。**

这一层不写方法（方法在 `../methods/`），只写**这个渠道能拿到什么、口径是什么、怎么进去**。

## 接口

每个 `channels/<id>.md` 的 front matter 是机器读的，下面的正文是给人读的。

```markdown
---
channel: xhs-spotlight
name: 小红书聚光 · 关键词规划工具
platform: 小红书
entry: https://ad.xiaohongshu.com/aurora/ad/tools/newKeywordTool
access: login_required
evidence_nature: official_commercial
status: verified
verified_at: 2026-09-29
---

## 能拿到什么
| 信号 | 记录字段 | 口径 |
|---|---|---|

## 口径限制（硬线）

## 采集步骤

## 已知陷阱
```

### 字段说明

| 字段 | 取值 | 是什么 |
|---|---|---|
| `channel` | kebab-case | 渠道 id。**原始记录里的 `channel` 必须在这里存在**——写错的渠道名校验器会拒 |
| `access` | `public` / `login_required` / `commercial_account` | 进去要什么权限 |
| `evidence_nature` | `official_commercial` / `official_creative` / `native_content` / `proxy` | 这批信号有多硬 |
| `status` | `verified` / `unverified` | **这个渠道真的跑过没有** |
| `verified_at` | 日期 | 上次真的跑通是哪天。平台会改版，这个日期是过期判断的依据 |

### 为什么 `status` 必须有

**没跑过的渠道不许写成跑过的。** 设计文档里写着「官方入口已确认，具体字段需登录后复核」的渠道，
在这里就是 `unverified`——它进不了采集流程，只能进「待建」清单。

`unverified` 的渠道文件**只写入口和待核实的字段**，不写口径限制和采集步骤——
那两节要真的跑过才写得出来，凭空写就是编。

## 证据性质四级

| 值 | 是什么 | 例子 |
|---|---|---|
| `official_commercial` | 平台官方商业工具直接返回 | 聚光关键词规划：月搜索指数、竞争指数、市场出价 |
| `official_creative` | 平台官方创作工具 | 创作灵感、创作话题、笔记灵感 |
| `native_content` | 原生内容信号，要人去读 | 搜索建议、笔记、评论 |
| `proxy` | 代理信号——**不是目标指标的替代品** | 微信指数之于视频号搜索量 |

**`proxy` 是硬线。** 微信指数测的是整个微信生态的关键词热度，不是视频号搜索量。
`AGENTS.md` 第 61 行写着「搜索指数、互动量、广告竞争度和市场出价是不同指标，禁止直接相加」，
这里是同一条规则在渠道层的展开。

### 待建

**待建渠道不写文件。** 写一个空壳文件，下次翻到会以为已经有了。它们住在这里：

| 渠道 | 入口 | 要核实什么 | 触发条件 |
|---|---|---|---|
| 小红书 · 原生搜索与评论 | 站内搜索建议、笔记、评论 | 搜索建议的接口形态、评论是否可批量读 | 需要「用户原话」时 |
| 抖音 · 指数 | 抖音指数（原巨量算数） | **具体字段**——旧文档只证明它提供过热词趋势，不证明现在的字段 | 需要抖音量级信号时 |
| 抖音 · 原生 | 搜索建议、作品、评论 | 搜索建议入口、评论可读性 | 同小红书原生 |
| 微信 · 指数 | 微信指数 | 入口可用性 | 需要微信生态代理信号时 |
| 视频号 · 原生 | 视频号搜索、话题、作品、评论 | **桌面端入口待核验** | 需要视频号原生信号时 |
| 视频号 · 创作者中心 | 单篇数据、作品诊断 | 需账号登录 | 有一方数据可读时 |

**下一个渠道由真实需求触发，不由蓝图触发。** 一次只加一个，加完跑通再加下一个。
