# 小红书 · 搜索结果页

**它不返回数字，返回内容。** 用途是算 SERP 重叠——判断两个词该不该合成一个簇。
方法见 `../methods/serp-overlap-clustering.md`。

和 `xhs-spotlight`（聚光）的区别：聚光给「多少人在搜」，这里给「搜出来是什么」。
**两个都要，不能互相替代。**

## 能拿到什么

| 信号 | 记录字段 | 口径 |
|---|---|---|
| 笔记 ID | `note_id` | 从 `/explore/<id>` 提取，**这是算重叠的指纹** |
| 标题 | `title` | |
| 作者 | `author` | |
| 点赞数 | `likes` | 平台原值照抄。**可能是 `赞` 这个字**，见「已知陷阱」 |
| 位置 | `rank` | 前排第几位 |

一次搜索返回 **约 27 条有效笔记**。

**但 `section.note-item` 抓到的是 30 个。** 多出来的 3 个是**广告位**，
不是笔记（2026-09-29 两次实测都是 30 → 27）。**按卡片数采会把广告位写进记录。**

识别方法只有一个可靠的：**广告位没有 `a[href*="/explore/"]`**，
它的 `data-note-id` 是形如 `06ed6b0b-cde2-4621-b274-2a9117b05008#1790676654908`
的 UUID 串——**带 `#`、不是 24 位十六进制**。

## 口径限制（硬线）

1. **结果是实时排序 + 个性化的。** 同词重测 Jaccard 只有 **0.80–0.93**，
   不是 1.0。**任何跨词重叠都要和这个噪声基线比，不能直接当绝对量。**
2. **点赞数是当前快照，不是历史累计。** 只用于判断内容的量级，不做趋势分析。
3. **这是原生内容，不是平台口径。** 它反映的是「平台认为该给你看什么」，
   不是「真实需求有多大」。**要量级去聚光，不要来这里要。**
4. **指纹必须用 `note_id`，不能用标题。** 标题会重复、会被改。

## 采集步骤

1. 用 `web-access`（CDP 直连本机 Chrome，带登录态）新建后台 tab。
   **ego-browser 的 profile 没有小红书登录态，用它会被挡在登录页。**
2. 导航到 `https://www.xiaohongshu.com/search_result?keyword=<urlencode>&source=web_search_result_notes`
3. 等 **9 秒**——小红书是 SPA，等短了拿到空列表。
4. 提取：`[...document.querySelectorAll("section.note-item")]`。
   **但笔记 ID 只能从 `a[href*="/explore/"]` 取**——卡片本身不是判据，
   广告位也是 `section.note-item`。**没有 `/explore/` 链接的卡片直接丢掉。**
5. **每个词之间等 ≥ 20 秒**（见「已知陷阱」第 1 条）。
6. 落盘到 `research/raw/<date>-xhs-serp-<slug>.json`。
   **一个文件可以装多个词**——见下。

### 落盘：一个文件可以装多个词，文件名只标主词

**文件名里的 `<slug>` 不代表文件里只有那个词。** 2026-09-29 实测：
`2026-09-29-xhs-serp-ai数字员工.json` 里装的是 **14 个词 × 各 27 条 = 378 条**，
`AI数字员工` 只占其中 27 条。

**所以算重叠、做统计之前，必须先按记录级的 `keyword` 字段过滤。**
把「一个文件」当成「一个词的集合」，算出的 Jaccard 会被集合大小差异挤成假低值——
27 条 vs 378 条的词对，真值 0.46 会被算成 0.07 上下，
**而 0.07 的意思是「平台不当它们是同一话题」，和真值 0.46 的「高相关」结论完全相反。**

**这是本渠道最容易犯的错里最隐蔽的一个**：文件本身没错、每条记录也没错，
**错在把「文件」当成了「词的容器」。** 读文件的人（或 agent）会从文件名推断内容，
而文件名在这里是不完整的。

**判断办法**：`len({r["keyword"] for r in records}) > 1` 就是批次文件。
**无论是不是批次，一律按 `keyword` 过滤**——单词文件过滤后不变，多词文件才是对的。

## 已知陷阱

- **连续快搜会掉登录态。** 2026-09-29 实测：约 6 秒一次连续搜 5–7 次后，
  页面返回「登录后查看搜索结果」，之后所有搜索都是 0 条。
  **冷却约 90 秒后自动恢复**，不需要重新登录。
  **每次搜索间隔 ≥ 20 秒，或分批采集。**
- **0 条不等于「这个词没有内容」。** 可能是风控、可能是页面没加载完。
  **看到 0 条先检查页面有没有登录墙，再下结论。** 把风控当成「无内容」是最容易犯的错。
- **低重叠 ≠ 不同意图。** 可能是内容稀缺（平台返回泛化结果）。
  **数字之后必须读内容。** 详见方法卡第五节。
- **`likes` 不一定是个数。** 除了数字和 `2.9万` / `1.2万` 这种，
  还会渲染成**中文字面值 `赞`**（数字还没渲染出来时，2026-09-29 实测）。
  **它不是 0，是「没读到」。** 照原值记，不要换算成 0——
  **把「没读到」记成 0，是编数**。
- **平台会改版。** 这个文件写的是 2026-09-29 的界面。下次跑如果对不上，
  改这个文件，不要改记录格式。
