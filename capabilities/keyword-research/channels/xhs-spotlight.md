# 小红书聚光 · 关键词规划工具

**第一个跑通的渠道**（2026-09-29）。另一个 verified 的是 `gdt-bidword`（腾讯广告 · 搜一搜）。
2026-09-29 用它做完了 `AI数字员工` 的词找词。

## 能拿到什么

三个页签，字段各不相同：

### 词根拓词

| 信号 | 记录字段 | 口径 |
|---|---|---|
| 关键词 | `keyword` | |
| 推荐理由 | `reason` | 平台原值，如「同行买词」「高点击」 |
| 竞争指数 | `competition` | 高 / 中 / 低 |
| 月搜索指数 | `monthly_search_index` | 平台自有口径 |
| 市场出价 | `bid_cny` | 元 |

### 上下游推词

同上一组，另加方向标记 `upstream_downstream`（上游 / 下游）。

### 用户路径拓词

**这个页签不是一张表，是一条路径上的多个节点，每个节点一套词表。**

| 信号 | 记录字段 | 口径 |
|---|---|---|
| 路径名 | `path` | 如「企业数字化转型路径」 |
| 路径词 | `keyword` | |
| 路径内用户占比 | `path_share_percent` | **路径内占比**，不是全站占比。填**该词所属节点**的占比 |

**路径和节点是两层，两层都要点（2026-09-29 实测）**：

- **路径**：`路径1 … 路径5 + 更多`，每条路径有自己的名字（「行业解决方案路径」
  「企业数字化转型路径」…）。**默认只显示路径1**，其余的要自己点。
- **节点**：一条路径上有 5–6 个位置（如「淘宝申诉判违规 22%」「店铺客服话术 30%」…），
  点 `css=.keyword-path-module-content-item >> nth=N` 切换。
  **每个节点一套词表，互不包含**——实测 `AI客服` 路径1 的六个节点分别返回
  18 / 7 / 32 / 17 / 8 / 14 条，合计 96 条。
- **只读默认状态 = 只拿到第一个节点的词**，少收 80% 以上，而且不报错。

### 全量导出（2026-09-29 新增）

每个页签都有「下载"所有词"」按钮，导出的就是该页签的全量结果，**不用翻页抓**。

**这次实测的导出格式**（2026-09-29）：

| 项 | 实测值 |
|---|---|
| 文件名后缀 | `.xlsx` |
| 实际格式 | **CSV 文本**（带 BOM）——`zipfile` 打开会报 `BadZipFile`，用 `file` 命令看到的是 `CSV text` |
| 出价列名 | **`市场出价`**（不是「市场出价(元)」） |

**读到 .xlsx 先验格式再解析**——直接按 Excel 处理会失败。用 `csv` 模块读，注意跳过 BOM。

**导出条数本身就是信号**：`智能体搭建` 导出 **434 条**、`AI数字员工` **30 条**、
`数字员工搭建` **6 条**、`AI同事` **1 条**。这个数反映平台在该词下积累的生态体量——
**是拓词前就能拿到的第一个量级信号**，不用等采集完。

## 口径限制（硬线）

1. **月搜索指数、竞争指数、市场出价分别保存，不做加总。** 三者量纲不同——一个是需求量、
   一个是难度、一个是价格。加总得到的数没有任何含义。
2. **用户路径里的占比是路径内占比，不与月搜索指数混算。** 路径里「数字员工 100%」
   意思是走这条路径的人都点了数字员工，不是搜索量。
3. **指数是平台自有口径，不跨平台比较。** 聚光的 370 和抖音的 370 不是一回事。
4. **出价高不等于自然内容一定受欢迎。** 出价反映的是广告主的竞价意愿，
   只能当商业意图的代理信号，不能当内容效果的证据。
5. **「上下游」是语义路径，不是内容池重叠。** 2026-09-29 实测：聚光把 `ai智能体`
   标为 `AI数字员工` 的下游（量级 19158，是主词的 52 倍），
   但两者在小红书 SERP 的重叠只有 **0.04**——读内容是技术主题，和「老板要雇一个 AI 员工」
   不是同一批内容。**语义相关 ≠ 内容可复用**，聚簇时不能拿上下游关系当合簇证据。
   见 `methods/cross-evidence-validation.md`。
6. **平台把大小写不同的写法当独立词条，各给各的指数。** 2026-09-29 实测：
   `AI数字员工` 指数 **370**、`ai数字员工` 指数 **825**——同一个词，两个条目，两个数。
   **这不是平台错误，是它的口径**（广告投放按精确匹配买词）。
   采集时**照抄平台给的写法**，归一留给系统的 `_normalize_surface()` 做；
   读数时记住这个数只对应当前写法。
7. **拓词结果只围绕种子词长，跨簇的词不会出现。** 想看某个词的数据，
   **必须拿它自己当种子搜一次**。2026-09-29 踩过：`智能体搭建` 不在
   `AI数字员工` 的拓词结果里，据此判「搭建类词没量」——实测它有 **17,936**（是 `AI数字员工` 的 48 倍）。
   **「在 A 的拓词结果里没看到 B」≠「B 没有量」。**

## 采集步骤

1. 用 `ego-browser` 开本机 Chrome（登录态），新开后台 tab 到 `entry`。
   **每次调用用同一个 task space 名**（如 `juguang-verify`），换名字等于每次新建空间，
   会读到空白页；脚本开头先检查当前 URL，必要时重新 `goto`。
2. 输入核心词，依次读三个页签。
3. **一次读一个页签，读完立刻落盘**，不要在对话里攒着——攒到最后会丢。
4. 落盘到 `research/raw/<date>-xhs-spotlight-<slug>.json`。
5. 噪音词进 `noise` 数组，写清为什么是噪音。
6. 现场发现的口径问题进 `notes`——下次遇到同一个渠道不用重新想。

### 操作细节（2026-09-29 实测，选择器可能随改版失效）

**搜索框是多选 select，不是普通输入框**：

- 展开：先点 `css=.d-select-content`——`.d-select-placeholder` 是 div 不是 input，
  直接 fill 会超时（零尺寸元素）
- 输入：`input[class*="color-text-title"]`
- **搜索完成后输入框会折叠成 0 宽**，要再填必须重新展开
- **换词前先删旧标签**：点 `css=.d-select-tags .d-tag .d-icon`

**结果表是虚拟滚动——这是最容易静默少收的地方**：

- `tbody` 只渲染视口内的行。实测 `AI客服` 的上下游推词页面写着「共 109 个关键词」，
  但 DOM 初始只有 50 行；滚到底后 `tbody` 甚至只剩 7 行。
- **「共 N 个关键词」不代表 DOM 里有 N 行。** 只读一次会拿到一个看似合理的子集，
  不报错、不缺页——和「数据在库里但页面是空的」是同一类静默失败。
- 全量取法：从 `table.parentElement` 往上找第一个 `scrollHeight > clientHeight` 的元素，
  `scrollTop` 从 0 按 ~120px 步进到 `scrollHeight - clientHeight`，每步读当前 `tbody`
  的行、累积去重。实测这样才拿全 109 条。
- 也可以用「下载"所有词"」（见下）绕开滚动。两条路都行，**但都要确认拿到了全量**。

**切换页签会清空种子词**：切「词根拓词 / 上下游推词 / 用户路径拓词」后搜索被重置，
必须重新输入种子词。三个页签的输入控件形态还不一样：

| 页签 | 输入控件 | 怎么触发搜索 |
|---|---|---|
| 词根拓词 | `.d-select-content`（div；点开后才出现 `input[class*="color-text-title"]`） | 填词后**按 Enter**——下拉里只有「创建"X"」一项，点它会被遮罩拦截 |
| 用户路径拓词 | 同上 | 填词后点 `css=.d-dropdown .d-option-content >> nth=0`（下拉是候选词列表） |
| 上下游推词 | 真的 `input[placeholder="请输入关键词"]` | 填词后点候选 |

**不要去填 `input[placeholder="请输入关键词进行搜索"]`（约 362px 宽）。**
那是右侧「已选关键词」区的搜索框，填了不会有任何反应——2026-09-29 在这里空转过一轮。

**全量下载**：`css=span:has-text("下载"所有词"")`——不要用 `:text-is("...")`，
含引号的文本会让 locator 解析失败。

**批量采集多个种子词时，每个词单独下载落盘**，文件名带词 slug。

## 已知陷阱

- **词根拓词会返回拼接噪音。** 2026-09-29 那次返回了 `AI漫剧额头上的数字结局`（3,283）、
  `生日数字烟雾ai图片指令`（1,447）、`风景如画_AI数字艺术`（709）、`京东ai购看图猜数字`（402）。
  平台按词面匹配，不理解语义。**这些要保留在 `noise` 里说明，不能默默丢掉**——
  丢掉的话下次看到同样的噪音还要重新判断一遍。
- **跨语义的同形词。** 同一次还返回了 `geo`（56,839）和 `geo优化`（31,897）。
  它们的指数很高，但和「AI 数字员工」不是同一个任务，必须排除。
  **指数高不等于相关**——这是最容易犯的错。
- **用户路径里的词可能没有独立指数。** 路径词很多是平台按行为聚类出来的，
  回到词根拓词里查可能是空值。**路径占比和搜索指数是两套数据，别互相补。**
- **虚拟滚动会让采集静默少收。** 见上「结果表是虚拟滚动」。2026-09-29 读 `AI客服`
  的上下游推词时，读数拿到 50 条、页面写着「共 109 个关键词」，**没有任何报错**。
  **数对不上就是信号**：每次读完先核对「共 N 个」和实际拿到的行数，
  不等就说明还没读完。同理，用户路径拓词只读默认节点也少收，但页面不会提示。
- **平台会改版。** 这个文件写的是 2026-09-29 的界面。下次跑如果对不上，
  改这个文件，不要改记录格式。
