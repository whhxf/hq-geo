# 关键词研究

**把「我觉得这个方向行」变成「有证据说明有人在用这种话表达这个需求」。**

这是创作链路最前面的一环。它在 `sourcing` 之前——**先知道市场在说什么，才知道要做什么内容**。

```
想法 ──关键词研究──→ 需求簇 + 备选选题 ──→ 选题记录 ──→ sourcing ──→ brief ──→ 内容
```

## 它是组合技能，不是一条流水线

同一个问题，在小红书、抖音、微信里要用不同的方式问，拿回来的口径也各不相同。
所以这一层的形状是**一组可插拔的渠道适配器**：

```
capabilities/keyword-research/
├── channels/          渠道适配器——加渠道就是加文件
│   ├── README.md      接口定义 + 待建渠道清单
│   └── xhs-spotlight.md
├── contracts/
│   ├── research-record.schema.json    一次采集的记录
│   └── demand-cluster.schema.json     归一化后的需求簇
└── scripts/validate_research.py
```

**渠道会改版，契约不会。** 平台改界面，改一个渠道文件；记录格式和归一化规则不动。

## 三类对象

| 对象 | 是什么 | 落在哪 |
|---|---|---|
| **原始记录** | 一次采集拿回的全部信号，不改写 | 项目根 `research/raw/` |
| **需求簇** | 按用户任务聚类后的判断 | 项目根 `research/normalized/` |
| **选题** | 讨论后的备选，要能答五问 | 项目根 `topics/<idea>/topics.json` |

选题的契约在 `capabilities/topic-registry/`——它**不是**本能力包的一部分。
研究产出证据，选题沉淀承诺，两件事的验收标准不同。

## 校验器拦什么

```bash
python3 capabilities/keyword-research/scripts/validate_research.py --project <项目根>
```

| 拦的 | 为什么 |
|---|---|
| **渠道名写错** | 记录里的 `channel` 找不到对应定义。写错不会报错，只会静默地采不到东西 |
| **记录与渠道定义对不上** | `access` / `evidence_nature` 两处必须一致，否则不知道这批数据有多硬 |
| **只有词没有数** | 除了关键词没有任何信号字段的记录，是手打清单，不是采集结果 |
| **编词** | 需求簇的代表词在原始记录里不存在。**这一条拦的是「想出来的词」** |
| **推断冒充证据** | 推断词混进代表词，或推断簇带了指数 |
| **没有出处的判断** | 簇没有 `evidence_refs`、账本缺来源或日期、闸门只给分不给理由 |

选题那侧由 `capabilities/topic-registry/scripts/validate_topics.py` 管。

## 证据性质四级

| 值 | 是什么 | 有多硬 |
|---|---|---|
| `official_commercial` | 平台官方商业工具 | 平台自己的口径，最硬，但只在平台内有效 |
| `official_creative` | 平台官方创作工具 | 官方聚合口径 |
| `native_content` | 原生内容信号 | 要人去读，但最接近用户原话 |
| `proxy` | 代理信号 | **不是目标指标的替代品**，只能当参考 |

**`proxy` 是硬线。** 微信指数测的是整个微信生态，不是视频号搜索量。

## 三条不做

1. **不做跨平台加总。** `AGENTS.md` 第 61 行：搜索指数、互动量、广告竞争度和市场出价是不同指标。
   平台之间也一样——小红书的 370 和抖音的 370 不是一回事。
2. **不产出事实。** 平台信号是需求证据，不是事实。要事实走 `capabilities/sourcing/` 的检索路径。
3. **不替用户选选题。** 系统给证据和判断，「做不做、先做哪个」是用户的决定。

## 和外部方法的关系

建这一层时评估过本机已有的三套关键词研究资产：

| 来源 | 抽进来 | 丢掉 |
|---|---|---|
| `evidence-first-keyword-research` | 证据分级、两阶段（先发现后立项）、五道门槛、去重规则 | Google/SERP/KGR/KD/Ahrefs 全套工具层 |
| `hq-mtsites/keyword-research` | Method Plugin 架构（= 渠道适配器）、provider 状态机 | **评分公式**——它给新站 SEO 用，`竞争低` 权重最高；内容获客的逻辑相反 |
| `AI-Writer/skills/keyword-research` | 无 | 全部 |

**为什么丢掉那套评分公式**：它算的是 `搜索量×0.35 + 竞争低×0.40 + 商业价值×0.25`，
竞争低占最高权重。那是**建站排名**的逻辑——新站打不了高 KD 词。

**内容获客的逻辑是反的。** 竞争高、出价高，说明商业意图强，正是该做的地方。
搬过来会把你导向「找没人搜的词」——那对建站有意义，对获客没有。
