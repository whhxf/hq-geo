# 关键词能力的场景识别与分流

**这份文件回答一个问题：这次该用哪一套关键词能力。**

关键词能力有两套，分属两个工作区。用错会拿到**不可比的口径**——
跨平台加总是宪法硬线（`AGENTS.md` 第 61 行）。

**边界判据不在这里。** 真源是
[`00-meta/content-engine/08-system-boundary.md`](../../00-meta/content-engine/08-system-boundary.md)。
本文只把那条判据落到关键词这一层，不另写一套。

---

## 一、三步路由

### 第 1 步：定目标平台

**受众决定选哪个平台。平台决定用哪套能力。** 所以路由的输入是平台，不是受众。

读任务或创意的**目标平台**。这是唯一的识别信号。

**不读定位卡的 `region`。** 那个字段记的是**卖家所在地区**，不是受众所在地区。
一个中国卖家把货卖给海外买家，`region` 仍然是「中国」——按它分流会分错。

### 第 2 步：按平台定能力

| 目标平台 | 关键词能力 | 能力落在哪 |
|---|---|---|
| 小红书 | 本包六站（`xhs-spotlight` + `xhs-serp`） | 本仓库 |
| 抖音 | 本包（`douyin-search`） | 本仓库 |
| 微信搜一搜 | 本包（`gdt-bidword`） | 本仓库 |
| 视频号 | **无**，待建 | 见 `channels/README.md` 待建清单 |
| Google / 自有域名 | KEYWORD-OS 五道门槛 | hq-chuhai |
| Reddit / X | 借 X 早期信号技能，只当线索 | hq-chuhai（产出归本仓库） |

**最后两行不是同一件事。** Reddit 与 X 是别人的平台，内容产出归本仓库；
但本仓库没有对应的渠道适配器，所以**能力是借的**。见第三节。

### 第 3 步：按要回答的问题选流程

两套能力回答的不是同一个问题，**不能互换**。

| 要回答的问题 | 用哪套 |
|---|---|
| 谁在什么场景下要完成什么任务？这篇内容写什么？ | 本包六站 |
| 这个词值不值得建站抢？做不做？ | KEYWORD-OS 五道门槛 |

## 二、两套能力的差别

差别不只是地区，是**产物**。

| | 本包（国内平台） | KEYWORD-OS（海外自有域名） |
|---|---|---|
| 数据来源 | 平台官方商业工具 + 原生 SERP | 第三方数据库 + 实时 SERP |
| 输出 | 需求簇 + 备选选题 | 做 / 观察 / 放弃 / 反驳 |
| 服务对象 | 平台上的读者 | 自有域名上的访客 |
| 判定方式 | 聚类依据 + 人工读内容 | 五道立项门槛 + 盘面质量 |

**推论**：需求簇不能当立项结论用，立项结论不能当选题用。

---

## 三、海外平台（Reddit / X）的现状

**这是缺口。现在用的是借来的能力。**

本包的四条渠道（`xhs-spotlight` / `gdt-bidword` / `xhs-serp` / `douyin-search`）
全是中文平台。海外平台内容没有对应的渠道适配器。

当前做法：借 hq-chuhai 的 X 早期信号技能做**发现**。

**借来的信号只当线索，不当判定依据。**

| 项 | 借来的信号 | 本包的渠道 |
|---|---|---|
| 证据性质 | 原生内容信号 | 官方商业口径 |
| 给不给量 | 不给 | 给 |
| 能不能跨平台加总 | 不能 | 不能 |

**两个口径不同的数放在一起比较，就是跨平台加总。** 这一条对本表三行都成立。

## 五、硬线

1. **跨平台不加总。** 小红书的 370 和搜一搜的 40 不是一回事。`AGENTS.md` 第 61 行。
2. **两套能力的输出不可互换。** 需求簇不是立项结论，立项结论不是选题。
3. **场景识别读目标平台，不读 `region`。** 定位卡的 `region` 是卖家地区。
4. **借来的海外信号只当线索。** 它不是官方商业口径，不给量。
5. **`unverified` 的渠道进去是试错，不是采集。** 见 `channels/README.md`。

## 六、不做

- **不在本包里复制 KEYWORD-OS 的门槛。** 那是另一个工作区的真源，两边各写一份就会漂移。
- **不为一次需求建新渠道。** 一次只加一个，加完跑通再加下一个。
- **不按受众所在地改边界判据。** 判据只有一条，改它要明确同意（08 第九节）。
