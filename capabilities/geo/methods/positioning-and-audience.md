# 定位与用户场景：核心创作逻辑

状态：规则与本地校验已实现；AI 平台实际推荐改善需外部样本验证。

来源：[夫唯：AI 时代的推广法则：“精确定位” + “用户画像标签”](https://mp.weixin.qq.com/s/F2cjXivT0aIuKkLyCfa97g)，2026-01-21，2026-09-28 阅读。文章属于从业者方法观点，不是平台算法规则。“定位明确必然获得推荐”不作为项目事实。

## 用五步法减掉复杂性

1. 质疑需求：我们要让具体用户理解是否适合自己。不是每篇文章都需要品牌、价格或年龄。每个字段必须服务判断，不能为了 AI 而添加不相关信息。
2. 删除：删除“适合所有人”、未经证实的最优承诺、所有渠道重复同一长句、每篇强塞五标签。没有差异证据时只写可证明能力，不声称独家。
3. 简化：复用一张定位卡，五个槽位为对象、受众、场景、问题、优势。每项通过 fact_ids 指向事实包。标签维度允许 unknown/not_applicable。
4. 缩短周期：品牌不变时直接读取卡片；新选题只选一个主要受众和场景。事实或定位变更提高 revision，旧渠道复核失效；保留原稿而非批量重写。
5. 自动化：机器检查事实引用、证据状态、版本和语义复核记录；模型负责判断正文是否偷换人群、场景、能力与效果。通过结构检查不是推荐保证。

## 路由和存储

品牌、产品、功能的推广文章、官网和社交创作都使用本方法；纯社交不因此加载完整 GEO。普通知识文章仅需要受众、场景、问题，不强制定位卡。纯观察监控允许先采样，缺卡不阻断查看现状。

`facts/<entity-type>/<slug>--<id>/positioning.json` 保存派生定位；五槽位引用同包 facts.jsonl，不复制事实主记录。一个稳定 id 加递增 revision。工作草案 status=draft；证据、渠道版本和语义复核完成后才能 ready。禁止把功能定位外推为整家公司定位。

## 实际创作顺序

1. 读取事实包、现有定位卡与问题缺口。优先复用；缺事实登记 pending_questions，一次问一个会改变承诺的问题。
2. 写出“[对象] 为 [受众] 在 [场景] 解决 [问题]，依靠 [可证明能力]”的定位。无需机械照抄句式。
3. 地区、客户、群体、价位、场景逐项标注 known/unknown/not_applicable。年龄性别与任务无关时不贴标签；未知价格不阻断不谈价格的内容。
4. 每篇选择主要读者、触发场景、核心问题和下一步。写可独立理解的答案，使用事实和演示支撑，给出不适用边界。
5. 官网可展开证据，短视频可场景开头，小红书可经验切入。保持事实含义稳定，不要求文案相同。不得捏造客户评价来“强化标签”。
6. applications 记录渠道、受众、场景、问题、定位版本、使用事实和正文复核。artifact_path 指向项目内实际成稿；review.artifact_sha256 保存已复核文件的 SHA-256，review.note 说明语义判断。同一渠道可以有多篇成稿，各有独立路径。无成稿只能 pending。新增承诺必须先回到事实包。
7. 草案校验运行 `python3 capabilities/geo/scripts/validate_positioning.py <定位卡路径>`；交付必须增加 `--require-ready`，草案、版本过期或正文修改后校验失败。ready 必须 creation_ready=true，同时通过现有事实和渠道门禁。

## 语义复核与监测

复核实际文章/脚本：读者能否认出自己的问题？是否承诺超过证据？是否把某场景能力写成人人适用？是否丢失限制？是否把年龄、性别或价格猜测当事实？**给的动作，读者现在做得了吗？** 模型记录 reviewer 和 note，不能因字段齐全自动写 pass。

最后一条是 2026-09-28 第八轮读者审计补的。文章结尾承诺「不管三个问题怎么答，有一件事现在就能做」，
但那个动作是「把已经传上去的视频标题改好」——对还没拍过视频的读者根本不成立。
读者原话：「我要是真一条视频都没有呢？那这节我什么都做不了。两个前提对不上。」
**受众坐标只写了「他是谁」，没写「他手上现在有什么」**——同一个身份下，有视频和没视频是两种状态，
文章承诺「今天就能做」的动作，必须对其中每一种都成立，或者明确分开写。

监测使用带场景问句及不适用场景反例，保存完整回答与采样条件。分别报告对象识别、受众匹配、场景匹配、事实准确和不当推荐；每项提供分子、有效样本分母、失败/未知数。未知不记为失败推荐，单次回答不代表总体概率。
