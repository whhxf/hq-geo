# 风格示例与风格库

**风格靠看，不靠读。** 文字描述说不清「口语一点」「别那么端着」，但并排放三段真实样例，一眼就能指出来。

文章、图片、视频三条流水线共用这套机制。每条流水线在定稿前都走这一站。

## 闭环

```text
外部样本  ──吸星大法──>  风格库  ──生成样例 HTML──>  你看，你选  ──>  应用创作
（别人的文章、       （提取特征，         （3 个候选，             （写进任务，
  某个账号、一本书）    存成条目）          真实素材）               记录修正）
```

风格库不是凭空长出来的，也不是一次性配好的。你看到好的就说「吸这个」，系统提取特征存下来，想用的时候调出来给你看。

## 吸星大法：风格怎么进来

你说「吸这个」，附上样本（一篇文章、一个链接、一段截图里的文字），系统做三件事：

1. **提取特征**——句长分布、节奏、人称、常用词与回避词、结构习惯、怎么表达不确定、怎么收尾；
2. **写进 `library.md`**——一个风格一节，写清来源、日期、特征、适用和边界；
3. **下次创作时作为候选**——生成样例 HTML 时，风格库里的条目优先于系统临时想的。

### 边界：吸的是特征，不是文本

- **可以学**：句长、节奏、结构、语气、信息密度、怎么处理反例。这些是方法。
- **不可以搬**：原文句子、独特比喻、具体案例、数据。这些是表达，受版权保护。

样本原文只作内部比对，**不进入任何对外产物**。`library.md` 里保存的样本片段要标注「仅内部比对」。

如果吸来的风格和某个具体作者高度绑定，在条目里写明，避免产出被误认为对方作品。

### 条目格式

```markdown
## <风格名>

- **来源**：<哪里吸来的>
- **吸收日期**：YYYY-MM-DD
- **样本**：<原文片段，仅内部比对，不进入产物>
- **特征**：
  - 句长：<均值与长短分布>
  - 节奏：<停顿、换行、分段习惯>
  - 人称：<第一人称经验 / 第三人称分析>
  - 用词：<爱用什么、回避什么>
  - 结构：<怎么开头、怎么收尾、有没有小标题>
- **适用**：<什么内容类型和平台>
- **边界**：<什么时候不该用>
```

特征写「怎么做」不写「感觉像什么」。「句子短」是特征，「很有力量」不是。

## 什么时候生成样例

进入实际创作之前，内容还是空白的时候。风格定完再写全文，不要写完再改风格——那是重写，不是选择。

## 生成什么

一个 HTML 文件，放在 `content/styles/<task-id>.html`。里面是 3 个候选，纵向排列，每个候选包含：

1. **风格名**（两三个字，如「直给」「叙述」「拆解」）
2. **一句话说明**（说清它放弃了什么，比说它是什么更有用）
3. **样例**（200 字左右，用当前任务的真实素材写）

三个候选必须是真正不同的路线，不是同一个东西换同义词。判断标准：如果用户看完说「都差不多」，这次生成就是失败的。

## 硬规则

- **必须用当前任务的真实素材。** 不许 lorem ipsum，不许「此处为示例文本」，不许拿别的选题凑数。用户看的是自己的内容，才能判断风格合不合适。
- **不许标注哪个是「推荐」。** 推荐会污染判断。用户要的是自己选，不是被引导。
- **HTML 要能直接在浏览器打开。** 不依赖网络资源，不依赖构建工具，双击就能看。
- **每个候选的排版要跟着它的风格走。** 「短句密集」就该看起来短，不能三段都套同一个样式。

## 选完之后

把选择写进任务文件的 `## 交付` 区块，格式：`风格：<风格名>（<一句话说明>）`。

同时记录**用户改过什么**。如果用户说「用第 2 个，但别那么碎」，那句「但别那么碎」比选择本身更值钱——它是对风格的直接修正。记在任务里。

累积到三次以上同方向的修正，才考虑沉淀成风格库（宪法第 8 条）。在那之前不要建。

## 和策略库的分工

- **策略库**（`../strategies/creative-strategies.md`）管**结构**：先讲证据还是先讲观点，用案例还是用清单。这些说得清，文字选。
- **风格示例**管**质感**：句子多长、什么语气、排版什么样。这些说不清，看 HTML 选。

两者独立。同一结构可以有不同风格，同一风格可以套不同结构。
