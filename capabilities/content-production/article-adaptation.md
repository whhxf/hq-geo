# 文章改编为图文与视频

状态：部分实现。已验证文件生产和单渠道草稿入口；不等于内容质量通过或已发布。

## 输入与产物

先读取母文章、事实包和目标渠道。保存文章路径、校验和与改编版本。不得把原文拆成几页或把同一截图推拉几次，当成完整改编。

- 图文：每页一个读者任务；封面承诺、步骤、结果、边界和下一步形成闭环。逐页记录事实引用与素材性质。
- 视频：先写镜头表，再写逐段旁白与声音方案。每镜明确观众将看到的变化，以及变化如何解释旁白。
- 工具教程优先真实操作录屏或真实输入与输出。动画引擎可做解释补充，但不能因为本地有某个 Skill 就把所有教程变成截图拼贴。
- 发布包：保留本地成品、文案、素材校验和、质量复核、平台预览和草稿回执。

## 先删再做

1. 质疑需求：这篇内容适合目标媒介吗？读者要看懂什么、完成什么？
2. 删除冗余：删除重复背景、重复截图、无解释作用的装饰和重复免责声明。
3. 简化优化：一个页面或镜头只推进一个判断。界面文字按手机实际显示尺寸检查。
4. 缩短周期：先验证关键一页或关键一镜，合格后再批量生产。
5. 最后自动化：满足三次真实重复才新增通用自动流程；单次案例脚本留在项目根。

## 质量阻断

任一项不满足，标记 `needs_revision`，不得标记可发布：

- 截图裁切后仍能看到承诺所需的关键内容；没有半截字、标签重叠或字幕遮挡。
- 相邻页面不靠同一截图和不同标题充数；边界卡可以使用明确标记的结构示意。
- 教程给出入口、输入、操作、检查和输出。仅有观点拆页不算教程。
- 视频的圈注必须精确指向解释对象；不能圈空白背景。快推指标不能替代讲解质量。
- 展示实际操作或效果时，使用实际素材并保留来源；缺素材先登记缺口，不能画一个假的产品界面。
- 独立复核实际成品，不只看脚本。修订后重新复核；旧结论不自动继承。
- 系统测试、媒体检查、人工质量判断分开记录。测试通过不能覆盖审片不通过。

## 草稿与发布

上传测试允许使用标明「验证草稿」且尚未达到质量要求的文件，但回执必须同时写明 `transport_verified` 与 `quality_status`，避免把通道成功误当成内容合格。

记录目标账号、入口、时间、文件校验和、预览结果与保存提示。平台未返回 ID 就不编造 ID。浏览器本地草稿不是云端备份，始终保留本地发布包。

公开发布另需用户明确授权。发布后必须核验实际链接，再进入数据回收与学习记录。
