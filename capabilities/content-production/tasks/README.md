# 任务约定

一次生产请求 = 一个任务 = 一个文件。

**这份约定住在系统根，任务文件住在项目根的 `tasks/`。** 所有项目共用这一份格式，
所以格式只改这里，不要在某个项目里另抄一份。

任务是实例层的入口单据。你在项目根的 `tasks/` 里写下要什么，Agent 在那里回写进度、产物和缺口。

## 怎么发布一个任务

1. 复制系统根的 `capabilities/content-production/tasks/_template.md`，在**项目根**的
   `tasks/` 下存成你的任务名（kebab-case 英文，如 `guangjiaohui-five-videos.md`）。
2. 填 frontmatter 的 `id`、`created`，和正文的 `## 任务` 区块。
3. 存盘。然后跟 Agent 说「看下 tasks 里的新任务」。

其余区块由 Agent 维护，你不用管。

## 文件格式

```markdown
---
id: guangjiaohui-five-videos      # 必填，与文件名去掉 .md 后一致
created: 2026-09-28               # 必填
deliverables: [article]           # 可选，默认 article
idea: <创意 id>                    # 可选，指向项目根 data/ideas/<id>.json
stage: intake                     # Agent 维护
status: needs_input               # Agent 维护
---

## 任务
（你写。Agent 只读不改。）

## 待确认
（Agent 写。缺料停机时把问题登记在这里，一次只问一个。）

## 交付
（Agent 写。产物路径、作者化检查结论、还差什么。）

## 分发登记
（你写。产物发出去之后回来补。）
```

**区块归属是硬规则。** Agent 不得改写 `## 任务` 和 `## 分发登记`；你不需要手动维护 `## 待确认` 和 `## 交付`。四个区块混着改，任务就失去可信度。

## 状态

`stage` 描述任务走到哪一站：

| stage | 含义 | 下一站的条件 |
|---|---|---|
| `intake` | 刚发布，Agent 还没读 | Agent 读完并列出缺口 |
| `research` | 正在补事实与素材 | 缺口清零，或用户明确说「就按现有的写」 |
| `drafting` | 正在写 | 母内容与渠道版本落盘 |
| `review` | 作者化检查 | 用户对每条检查做出接受/保留决定 |
| `delivered` | 已交付 | 用户分发 |
| `distributed` | 已分发并登记 | — |

`status` 描述任务当前是否卡住：`needs_input`（等用户回答）、`in_progress`、`blocked`（缺料停机）、`done`。

`stage` 和 `status` 只由 Agent 写入，且必须能追溯到文件——产物在 `## 交付` 里有路径，缺口在 `## 待确认` 里有条目。不允许只改状态不给依据。

## 分发登记怎么填

产物发出去之后，回到任务文件补这一节。**这是判断系统有没有用的唯一原始数据**——不填，系统就只能证明自己没坏，不能证明自己有用。

| 日期 | 渠道 | 链接 | 效果 | 备注 |
|---|---|---|---|---|

- **日期 / 渠道 / 链接**：分发当天就填，30 秒的事。
- **效果**：过几天有数据了再回来补。写原始数字加一句话，不用凑格式——视频号看播放，博客看阅读，媒体看转载，指标本来就不一样，强行统一只会逼你编数。
- **备注**：什么意外都写。发出去没人看、评论区吵起来、有人私信问价——这些比数字有用。

**「没效果」也要写。** 一条发了没动静的记录，比十条只记成功的记录更能说明问题。

**不要美化。** 登记是给自己看的，不是给系统交作业。数据难看，正是系统需要知道的。

## 命名

`kebab-case.md`，说清楚是什么任务，不要编号（编号在排序时会骗人，任务靠 `created` 排序）。

不要用 `new`、`latest`、`最终版` 这类失去时间含义的词。

## 清理

`stage: distributed` 且超过 90 天的任务移到 `tasks/archive/`。归档不删除：分发登记是判断系统是否有效的原始数据，删掉就再也算不出效果。

未分发的任务不清理——它们要么在等你的决定，要么暴露了系统的真实卡点。

## 与其他目录的关系

- `data/ideas/` — 创意，长期存在，可以产出多个任务
- `topics/` — 选题池，一个任务通常锁定其中 1 个
- `facts/` — 事实包，任务缺料时 Agent 把问题登记进 `## 待确认`，回答后补录进事实包
- `content/` — 产物落盘位置
- `assets/generated/` — 外部制作系统回传的成品

任务本身不保存事实和产物，只保存指针。真源永远在各自的目录里。
