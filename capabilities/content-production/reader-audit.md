# 读者审计：提问脚本

站 6 第三道检查用的提问脚本。**必须由一个没参与写作的独立 agent 执行。**

## 为什么要有这一道

2026-09-28 实测。一篇稿子：事实标注齐全、免责声明到位、三道合规检查全过、Gate C 归零。
把全文交给一个独立 agent，设定成目标读者，读完的判词是：

> **「这篇文章把我劝住了，但没把我劝动。」**

它抓出六条，写稿的人自审一条都没抓到：

| 抓到的 | 写稿的人当时怎么想的 |
|---|---|
| 身份交代那句「我们是 XX，做外贸企业的视频工具」是划走点 | 加它是为了「让读者知道谁在说话」 |
| 「你在等它自动带来询盘」是废话——「这我知道，我又不是傻子」 | 事实包里有这条边界，不写会漏限制 |
| 案例段「多少流量？几个询盘？」——读者上火 | 已按事实纪律标了「非第三方审计」 |
| 案例里那个能立刻做的动作被埋住了，「该在『你现在能做什么』那节」 | 案例段是完整的一节，动作放在里面顺理成章 |
| 结尾工具清单「把前面攒的那点信任花掉了一半」 | 结尾总要说一下产品 |
| 读者读完的行动是「先查后台数据」，不是找品牌 | 以为文章建立了信任 |

**结论**：写稿的人审不出自己的盲区。合规检查只能防错，不能产生读者价值。
这一道必须换人——不是换标准，是换视角。

## 怎么执行

用 Agent 工具起一个 `general-purpose` agent。**给它的只有两样东西：**

1. **成稿全文**（原样贴，不要加解释、不要加小标题、不要标注重点）
2. **读者身份**（站 1 定位卡的 `applications.audience` + `scenario` + `problem`，写成一句处境）

**不要给它**：写作背景、核心判断、策略 ID、风格说明、你希望它注意什么、
哪一段是重点、哪一段你觉得写得不好。**它知道得越少，越像真读者。**

**渠道信息要给**：如果稿子是为某个平台写的，告诉它「你在 X 上刷到这篇文章」，
以及账号名和简介（读者看到的就是这些）。这是真实阅读场景的一部分，不算作弊。

## 提问脚本

把下面这段和成稿一起交给 agent。**方括号里的内容按项目替换。**

---

你是一个读者，不是编辑，不是评论家，不是内容专家。

**你的身份**：[受众身份，例：中国外贸 B2B 企业的老板或业务负责人。公司有独立站，有流量，但询盘少。你最近在琢磨要不要给网站加视频。]

**场景**：[阅读场景，例：你在今日头条上刷到了下面这篇文章。发布账号是「KingswayVideo」，账号简介写着「助力外贸B2B用视频拿自然流量和询盘」。]

请完全代入这个身份，把文章读完，然后回答问题。

**回答要求（很重要）**：

- 用你自己的话，**不要抄原文**，不要复述文章说了什么
- 不要客气，不要夸，不要说「这篇文章很好」这类话
- 只报告你真实的反应。觉得无聊、觉得像广告、觉得是废话，直接说
- 回答要具体到句子。不要写「第二部分比较好」这种话，要写「第几段那句让我想划走」

**问题**：

1. 刷到标题和开头三行时，你会点进去吗？为什么？（先只看标题和前三段，再往下读）
2. 读的过程中，哪一段你最想跳过？哪一句让你卡住、看不懂、或者觉得是废话？读到第几段你会想退出？
3. **逐节回答**（按 `##` 分节，加上开头的无标题部分）：读完这一节，你比读之前多知道了什么？用你自己的话说。如果答不出来，就直说「这一节我拿不走东西」。
4. 关掉文章，你能跟同行复述出什么？（一到两句，用你的话）
5. 你会把它转给同行吗？什么情况下会，什么情况下不会？
6. 读完你打算做什么？如果什么都不打算做，说清楚为什么。

---

**文章全文**：

[成稿原样粘贴]

---

**输出格式**：按问题编号 1-6 回答。第 3 题要逐节回答，每节都要有。语言用中文，口语化，像一个真实的读者在说话。

## 判红标准

任一条成立，稿子就不得进站 7：

- 有哪一节，读者说不出「多知道了什么」
- 有哪个位置，读者明确说「想退出 / 想跳过 / 是废话」
- 读者读完说不出「打算做什么」
- 读者对某段的理解与站 5 的「读者获得」声明相反

**红了就逐条处理**：给改法，或者说明为什么不改。不许只写「保留」。

## 什么时候停

**最多两轮。** 2026-09-28 Conan 定的线：**「以后限定一下，最多做 2 轮检查，将发现的问题修复 2 轮即可，文无第一，永远都有最好的版本。」**

第一轮审 → 改 → 第二轮审 → 改 → **交付**。第二轮之后不管还剩什么，都记 `BACKLOG.md`，不再审。

**为什么需要这条硬线，而不是靠下面的判据**：2026-09-28 第一篇稿子审了十六轮。前几轮是必要的
（建立检查、撞出系统缺口、渠道从「先不定」改成今日头条后内容取舍全变），但后十轮里有一半的返工
是**改稿自己引入的**——加一段，下一轮说它重复；再补一句，下一轮说它是空话。
问题层次降到措辞之后，**每一轮都还能挑出「可以更好」的地方，因为这个层次永远有更好的版本**。
判红四条和「看收敛方向」都拦不住它：它们能判断「这一轮有没有问题」，判断不了「还该不该继续」。

下面的判据仍然有效，用在**两轮之内**：

- **判红四条**是硬标准，触发就必须改
- **不触发判红、读者只说「这样更好」的**，不是判红项——记进 `BACKLOG.md` 或留到下一版，**不阻塞交付**

读者永远能挑出「可以更好」的地方。没有这条线，审计会变成无限循环，
最后一稿改到谁也不认识，而每一轮都「有理由」。

**判红第 2 条要区分「真退出」和「相对最想跳过」。** 2026-09-28 十六轮实测的教训：
问读者「哪一段你最想跳过」，**他总会挑一段**——这是问题的形式决定的，不是文章的问题。
第 14、15、16 轮读者说的都是「最想跳过的一段」「差一点就划走了」「那一下确实想退」，
但三轮紧接着都说「是被后面某句拉回来的」「就留下了」。**这不是判红，是改进项。**
判红的是「读到这儿我不读了」「我直接拉到底了」。
写稿的人很容易把前者当后者——「读者卡了」是真的，但**卡了不等于走了**。
**注意这不是放松标准**：真退出仍然必须改，改完再审一轮；这条只防止把「相对最没意思的一段」
当成「读不下去的一段」。两者都值得改，但后者阻塞交付，前者记 BACKLOG。

**这条教训的代价要写下来，因为它不是理论**：第 10—16 轮里，有一半的返工是这么来的；
而更早的第 10—13 轮，读者抓到的「新问题」**大半是上一轮改稿自己引入的**——
加一段，下一轮说它重复；再补一句，下一轮说它是空话。
**改稿本身在制造问题，而审计把每个新问题都当成了新证据，于是循环起来。**
正确的停法是看**问题层次**：措辞 → 结构 → 论证是收敛，上一轮修掉的没再出现就该收；
层次降到措辞（对仗句、黑话、某个短语不适用）时，那些是改进项，不是继续改的理由。

**看收敛方向，不只看条数。** 2026-09-28 一篇稿子连审三轮，问题层次在变深：

| 轮次 | 抓到的 | 层次 |
|---|---|---|
| 第一轮 | 身份交代句是划走点、「你在等它自动带来询盘」是废话 | 措辞 |
| 第二轮 | 「它让我做题，没给我做完题之后的下一步」 | 结构 |
| 第三轮 | 「一百人零询盘不是流量不够」「哪一步要拍新视频了？都不需要」 | 论证 |

措辞 → 结构 → 论证，**是收敛**：上一轮修掉的东西没再出现。

**如果新一轮又抓出同量级的结构或论证问题，那不是要接着打补丁，是这一稿的底子有问题——
退回站 5 重写，不要在上面继续糊。** 打补丁改的是句子；底子的问题是这篇文章要回答的问题错了。

## 抓出来的问题分两类

**判红项**（判红四条触发）→ 必须处理，逐条给改法或说明为什么不改，写进任务的 `## 交付`。

**改进项**（读者说「这样更好」但没到判红）→ 记进 `BACKLOG.md` 或留到下一版。
不要因为「读者提了」就全改——**读者说的是体验，不是指令**。
有些是渠道策略问题（比如「官方号发的文章，转出去会被当广告」），改稿子解决不了。

## 论证层的问题，读者审计在替受众复核补位

2026-09-28 第三轮实测：读者抓出的四条——以偏概全、单一归因、自相矛盾、同义反复——
**每一条都属于站 6 第二道「受众复核」里「是否承诺超过证据」该管的**，但一条都没抓到。

原因和第二道建立之前是同一个：**受众复核也是写稿的人自己审自己。**

所以：**读者审计抓到的论证层问题，要回头在任务的 `## 交付` 里记一笔，
写明受众复核为什么漏了它。** 这不是追责，是让受众复核有改进的输入——
不然它会一直停在「四条答完就过」的形式上。

## 已知的坑

- **不要问「你觉得这篇文章怎么样」**——那会得到一篇评论，不是读者反应。
  要问「你会点进去吗」「读到第几段想退出」，问的是**行为**，不是评价。
- **不要让它总结文章**。要求里明确写了「不要复述文章说了什么」——
  否则它会写一篇合格的摘要，你会误以为审计通过了。
- **逐节问，不能只问整体**。整体问会得到「还行」，逐节问才会暴露「这一节我拿不走东西」。
- **读者身份要具体到处境**，不能只给一个标签。「外贸老板」太宽，
  「独立站有流量但询盘少，最近在琢磨要不要加视频」才能让他对号入座。
- **一次审计不等于结论**。它抓出来的是**具体位置的具体问题**，可以直接改；
  但它说「好」的地方不代表真好，只代表这个视角没看出问题。
- **改稿优先删，不优先加。** 2026-09-28 连着两轮，读者抓到的「重复」都是上一轮改稿时
  **加了一段**造成的：第六轮是把内容挪进另一节却忘了删原位；第八轮是为了呼应账号简介补的一段，
  和已有的「接住需求不创造需求」撞了。**加的内容必然跟已有的争同一个位置。**
  改完一稿，给每个新增段落找出「它和哪一段说的是同一件事」——找得到就是重复，
  该做的是**替换**，不是追加。这条不是文风洁癖：读者抓到的重复，是判红四条里
  「想跳过」的直接来源，而写稿的人连着两轮都没自己看见。
- **补「照顾某类人」的句子，要给那类人认得出的落点。** 上一条管的是新内容和旧内容**重复**，
  这一条管的是新内容**停在抽象层**——两回事，都可能被判红。
  2026-09-28 第十二轮读者指出「让人相信的镜头」一节默认读者有厂（「车间里有活、检测在做」），
  补了半句「没有工厂的，拍你手上正在办的事」。第十三轮读者正是贸易商，判词分两半：
  「**是全文唯一戳到我的地方**」——方向对了；「什么叫『手上正在办的事』？拍我验货？
  跟工厂打电话？展会？打包？**一个例子都不给。这是全文最大的空档。**」——落点没有。
  那半句把他**包含进来**了，没给他**下一步**。对照同一节的写法：另外两个判断后面都跟着
  读者认得出的动作（「原料怎么进、机器怎么走、质检卡在哪一道」），只有新补的这半句停在抽象层。
  判据：**把新加的那句读给那类人听，他能说出「那我明天做什么」吗？**
  这条和受众复核第五条（「给的动作，读者现在做得了吗？」）是同一根线的两端——
  那条问动作对这类人**成不成立**，这条问动作对这类人**够不够具体**。
